# 与 4 号联调清单（RAGTool v1.4 Hybrid RAG）

## 4 号需要接入的文件

```text
tools/rag_tool.py
rag_core/                 # 整个目录
requirements.txt
requirements-lock.txt        # 论文实验精确版本
```

先执行：

```bash
python3 -m pip install -r requirements.txt
```

第一次 `prepare()` 会下载公开 Embedding 模型；合同向量随后使用本地缓存。默认内部同时执行
Embedding 与 BM25 融合检索，但 `prepare/retrieve/verify` 调用方式不变。无需向 4 号提供 DeepSeek 模型函数，
本模块自己的 `deepseek_client.py` 负责语义核验。

## Agent 调用顺序

```python
rag = RAGTool({"chunk_size": 800, "chunk_overlap": 120})

prep = rag.prepare(document_id, file_path)
assert prep["status"] == "SUCCESS"

retrieved = rag.retrieve(
    document_id=document_id,
    query=task["question"],
    top_k=task["top_k"],
    category=task["category"],
)

verification = rag.verify(
    document_id=document_id,
    category=task["category"],
    category_answer=extraction["category_answer"],
    predicted_answers=extraction["predicted_answers"],
    retrieval_history=history,
    question=task["question"],
)
```

## 4 号必须注意

- `category` 虽可省略，但应显式传入；不要让 RAG 工具猜任务类别。
- 抽取出的块内位置必须加上块的 `start`，变成全文 `answer_start`。
- `score` 是融合排序分数，不是风险概率或条款存在概率；需要时可查看 `dense_score/bm25_score`。
- 结构补充后以 `rank` 和返回顺序为准，不要自行按 score 重排；`retrieval_sources` 可记录 structure。
- `retrieval_confidence` 未做概率校准；`LOW` 只表示建议补查，不能直接判定条款不存在。
- 未知 `category` 会返回 `UNSUPPORTED_CATEGORY`；通知续约的兼容别名会自动归一。
- `prepare` 返回 `INDEX_TRUNCATED` 时不可继续，这表示完整合同未被索引。
- 每轮保存 `query/top_k/retrieved_chunk_ids`，否则 `No` 的覆盖核验无法成立。
- `prepare.status != SUCCESS` 时停止当前合同，不要继续抽取。
- `verify=FAILED` 时重新抽取；`UNCERTAIN` 或覆盖不足时补查或转人工。
- `No` 即使覆盖充分，没有引用也返回 UNCERTAIN/NO_EVIDENCE。不要把覆盖充分当作答案正确。
- `SEMANTIC_CONTEXT_TOO_LARGE` 表示超过全文语义送审预算；按现有 UNCERTAIN 路径处理。

## 3 号需要读取

```text
category
category_answer
predicted_answers（原文 + answer_start）
verification_status
coverage_status
evidence_checks
```

`verification_status != PASSED` 或 `coverage_status == INSUFFICIENT` 时，不应输出确定性的风险等级。

## 验收清单

- [ ] `prepare` 返回 `retrieval_mode=embedding`、`retrieval_strategy=hybrid`
- [ ] 一份合同的 11 类任务全部跑通
- [ ] 每个命中包含 `text/start/end/score/page`
- [ ] 错误偏移触发 `POSITION_MISMATCH`
- [ ] 覆盖不足的 `No` 触发 `COVERAGE_INSUFFICIENT`
- [ ] 全文零锚定词的 `No` 同样不会自动 `PASSED`
- [ ] 全文锚点已覆盖但没有引用的 `No` 仍为 UNCERTAIN
- [ ] 同 ID 重新 prepare 失败后不继续使用旧合同
- [ ] 日志能回放每轮 query 与 chunk IDs
- [ ] 仓库不包含 API Key、`.env`、`.venv`、模型权重或缓存

完整字段和失败码见 `docs/RAGTool_对接说明.md`。
