## 1. 业务场景

本项目面向企业交易及日常商业合作中的合同初步审查。企业业务人员、法务或交易审查人员需要从较长的合同中找到重要约定，了解交易完成后继续履行、退出合作及承担责任的条件，并将需要进一步确认的事项交由人工复核。

例如，在企业收购前的合同尽职调查中，审查人员需要确认目标企业的重要合同是否约定控制权变更限制、交易后是否需要取得对方同意，以及合同终止和责任承担的相关安排。判断这些问题时，单独找到关键词通常不够，还需要阅读适用主体、触发条件、例外和交叉引用。若输出只有风险结论而没有原文依据，审查人员仍需重新查找合同，难以判断结论是否可靠。

项目拟从 CUAD 商业合同中选取有限数量的合同和 3–5 类目标条款开展研究。CUAD 官方将其定位为支持企业交易、包括并购相关合同审查的条款识别数据集，因此适合作为本项目的公开数据起点。<sup>[1]</sup>

本阶段建议选择控制权变更条款、合同转让限制条款、无须违约事由的终止条款、赔偿责任限制条款，以及赔偿责任不设上限的条款五类，具体定义和覆盖统计见第 5 节。以企业现有商业合同初审为基础场景，并购尽调作为应用例子；候选清单包含多种合同类型，不将全部样本表述为并购合同。范围作为本阶段明确建议，供小组统一后冻结。

系统输入拟包括合同原文、审查立场、目标条款及预设审核政策；输出拟包括条款识别结果、关键事实、规则核验状态、具备依据时的风险提示等级，以及原文位置和人工复核建议。审查立场须具体到所代表的一方，并在同一次比较中保持一致；同一条款对不同当事方的影响可能不同。

## 2. 研究问题

本项目的核心研究问题是：**如何构建结合 RAG 与规则核验的商业合同审查 Agent，实现目标条款识别、依据预设审核政策生成风险提示，并提供可追溯的原文证据与人工复核信息？**

围绕这一问题，拟关注以下方面：

1. 条款识别：系统能否找出相关条款，并保留影响解释的主体、条件、否定和例外，减少遗漏与误识别？
2. 规则判断：在审查立场和审核政策固定的条件下，系统能否一致地判断规则是否触发，并在事实不足时保留“无法确认”状态？
3. 证据追溯：每项事实和风险提示能否关联到真实合同原文及位置，且引用内容能够支持相应判断？
4. 使用代价：增加检索、核验和补查后，需要付出多少时间、模型调用成本及人工复核工作？

通过基准实验评价系统的条款识别、规则执行、证据追溯及运行成本，分析其适用范围与局限，不预设其优于直接使用大语言模型。本项目的价值在于将指定合同资料、预设审核政策与证据核验结合，构建符合特定业务要求、审查过程可追溯的合同审查 Agent。拟通过组织专用合同知识库、配置审核规则与固定检查清单，使系统围绕明确的资料范围和审查立场执行任务，并保留原文依据、政策版本及人工复核信息；具体效果仍需实验验证。

具体比较方案、实验设计与指标口径由理论设计及实验成员共同确定；比较时应明确并控制合同样本、目标条款、审查立场、审核政策和基础模型等条件。

风险提示等级表示既定审核政策下的关注程度。规则触发不直接构成违法认定，未触发也不代表合同整体没有风险；未检索到条款时，应继续核查或标记不确定，不能直接判定该条款不存在。

## 3. 业务价值与研究边界

本项目拟提供以下价值，实际效果需通过实验验证：

| 预期价值 | 具体体现 | 后续可观察的证据 |
| --- | --- | --- |
| 辅助定位审查重点 | 按目标条款组织检查事项，提供相关原文及关键事实 | 条款识别的准确性与覆盖情况 |
| 便于人工核查 | 将提示与原文位置、规则依据关联，减少重新查找材料的负担 | 引用位置有效性、证据支持情况及复核耗时 |
| 便于核查规则执行是否准确 | 记录每项判断使用的合同事实、规则编号和触发条件，便于检查系统是否按预设审核标准作出判断 | 在相同审查立场和审核政策下，规则触发状态及风险提示等级相对于人工核验参考结果的正确率与错误情况 |
| 明确需要人工复核的事项 | 对证据不足、例外不清及工具失败保留状态并提出复核要求 | 弃答、判定覆盖与人工转交情况 |

本阶段以英文合同文本及字符位置追溯为基础，围绕选定条款开展事项级审查。PDF/DOCX 上传、页码定位、合同整体风险汇总及修改文本生成暂不作为首版研究成立的必要条件。项目不要求自行训练基础大模型；具体模型与运行方式由系统成员结合资源条件确定。

CUAD 的条款标注可用于评价条款识别与定位，不能直接作为本项目高、中、低风险等级的参考答案。风险判断需要配套的审核政策及经人工核验的补充标签。人工参考答案应与 Agent 运行输入隔离，避免评价时泄露答案。

版本与时效：拟记录本次审查所用的合同及补充协议版本、审核政策版本和审查日期；如引用法律资料，还需注明来源、适用法域及生效时间。相关依据更新后，应标记受影响的结果供人工复核。首版不自动判定法律修订对合同效力的影响；资料时效或法律适用无法确认时，应明确提示人工核查。

### 4.2 数据字段

| 字段 | 含义 |
| --- | --- |
| `data[].title` | 合同标识，对应 CSV 的 `contract_title`，需精确匹配 |
| `paragraphs[].context` | 合同原文；当前完整数据每份合同有一个 paragraph 条目 |
| `paragraphs[].qas[].id` | 问题标识，末尾 `__` 后为条款类别名 |
| `question` | 标注问题及类别说明；这是一种数据格式，不要求产品让用户逐条提问 |
| `is_impossible` | 当前问答项的无答案标记 |
| `answers[].text` | 人工标出的原文片段 |
| `answers[].answer_start` | 从 0 开始的起始字符位置；不是页码或字节偏移 |

一个问题可有零个或多个答案片段。“有答案”表示该类别有参考标注，“无答案”表示答案列表为空。两者均不直接表示高低风险；尤其不能把运行时没检索到证据等同于合同没有条款。清洗和分块应保留原始字符位置映射，人工答案及 CSV 中的标注计数仅供数据筛选、人工检查和评测，不输入 Agent 检索库。

### 4.3 标注示例与位置核对

例如，合同标识 `CENTRACKINTERNATIONALINC_10_29_1999-EX-10.3-WEB SITE HOSTING AGREEMENT` 中，“无须违约事由的终止条款”类别的一段标注为：

> Either party may terminate this Agreement without cause at any time effective upon thirty (30) days' written notice.

译意：任何一方均可在不以对方违约为前提的情况下终止本协议，提前三十日书面通知后生效。片段起点为 `10880`，长 `116` 个字符，`context[10880:10996]` 与原文一致。译文仅辅助理解，评价以英文原文为准。该合同属于官方测试集，已用于本说明的学习示例，因此从本次预留测试候选中排除。

已对完整数据全部 13,823 个答案片段执行 `context[start:start + len(text)] == text`，位置不匹配数为 0；所有问答项的答案空值与 `is_impossible` 标记一致。这是数据结构检查，不是 Agent 效果或人工法律审核结果。

| 合同转让限制条款 | `Anti-Assignment` | 374 / 136 | 302 | 72 | 654 |

| 赔偿责任不设上限的条款 | `Uncapped Liability` | 111 / 399 | 98 | 13 | 167 |

| 类别 | 选择理由及拟识别内容 |
| --- | --- |
| 控制权变更条款 | 与并购、股权或业务变化情境相关；定位通知、同意或终止条件，注意定义与例外 |
| 合同转让限制条款 | 与权利义务转移及交易后履行相关；识别谁需要同意、是否允许关联方或继受方转让 |
| 无须违约事由的终止条款 | 无须对方违约等特定事由即可终止合同；识别享有该权利的一方、通知期限及其他约定条件，并非不受限制地随时退出 |
| 赔偿责任限制条款 | 与责任暴露相关；官方类别还可能包括索赔期限或责任范围限制，不能一律解释为金额上限 |
| 赔偿责任不设上限的条款 | 与责任限制配合检查；可能仅对特定违约、保密或知识产权事项不设上限，不能理解为合同中的所有责任都不设上限 |

最后两类可能同时出现、甚至共享片段，需要结合上下文解释。选择五类的理由是业务关联明确、存在正向标注且有无答案对照，并能覆盖主体、条件、例外和交叉引用等检索难点；并非因为已经测得模型在这些类别上表现较好。具体规则阈值和风险等级由规则成员确定，本任务不代填法律结论。

## 6. 样本筛选方案与实际筛选记录

### 6.1 样本规模与范围

本次形成 **20 份真实合同的拟用清单：12 份开发候选、8 份预留测试候选**，共对应 100 个“合同 × 目标类别”检查项。该规模是课程首轮开发和核查的可控起点，不是统计充分性保证，也不是最终样本量承诺。最终交付时根据运行资源和类别覆盖更新清单，并记录变更原因。

候选合同含分销、服务、供货、许可、联合开发、推广等类型。CSV 的合同类型仅按原始标题概括，未冒充逐份全文审阅结论。目标场景为企业商业合同初审，不声称样本均属于同一行业、合同类型或适用法域。

### 6.2 纳入、排除与划分规则

1. 使用固定版本 `CUADv1.json`，合同标识可在官方训练或测试文件中唯一找到；保留官方合同级划分，不将同一合同切成开发和测试两部分。
2. 原文为非空字符串，五个目标类别均有对应问答项，答案位置核对通过；不改写原文、不截断后半部分来满足长度要求。
3. 首轮限定原文 **5,000–60,000 个字符（含空白）**，以控制阅读、调用和复核成本。上下限是本项目的资源选择，不代表合同质量标准；字符数也不等于 token 数。短文本和超长文本暂缓，不作法律有效性判断。
4. 对 UTF-8 编码的原文计算 SHA-256。相同原文只保留合同标题按 Python 字符串顺序排序后的首个条目；已展示答案的学习示例另行排除。
5. 从官方训练部分选 12 份开发候选，从官方测试部分选 8 份预留测试候选。开发部分每类至少有 3 份有答案、3 份无答案合同；测试部分每类至少各 2 份。无答案是官方标注状态，不是人工认定该条款绝对不存在。
6. 使用标题提取的主体前缀去重，使清单不重复选取同一主体前缀。按 `_月_日_年`、`_YYYYMMDD_` 或 ` - ` 的首个匹配处分割，前缀经 NFKC、casefold 和仅保留字母数字处理。该方法仅作初步防重，不能识别全部关联企业或近似模板。
7. 在各自集合内逐份选择：对每个候选，统计它能补足多少项“类别 × 有/无答案”最低配额；优先选择得分最高者，并以 `SHA256("20261102|" + contract_title)` 的十六进制字符串升序打破并列。先选开发 12 份，再选测试 8 份；达到配额后仍按同一规则补足数量。整个过程不读取模型输出或依据模型表现挑样本。

| 按顺序执行的筛选步骤 | 排除数 | 剩余数 |
| --- | --- | --- |
| 官方完整数据 | — | 510 |
| 原文少于 5,000 字符 | 38 | 472 |
| 原文多于 60,000 字符 | 145 | 327 |
| 原文 SHA-256 完全重复 | 1 | 326 |
| 已用于标注教学示例的测试合同 | 1 | 325 |
| 按配额及确定性排序形成阶段清单 | 305 份保留为未选候选，不判为无效数据 | 20 |

完全重复的一组为 `ADUROBIOTECH,INC_06_02_2020-EX-10.7-CONSULTING AGREEMENT` 及其 `(1)` 版本，二者原文一致。筛选后候选池为 263 份官方训练合同、62 份官方测试合同。上述 305 份未选合同仍可用于之后扩充。

## 7. CSV 字段与使用方法

配套交付：[sample_manifest_draft.csv](./sample_manifest_draft.csv)。UTF-8（带 BOM，便于 Excel 识别中文）编码、标准逗号分隔、首行为表头，每份合同一行，共 20 行数据。CSV 不包含合同全文或答案原文。

| 字段 | 含义与使用约定 |
| --- | --- |
| `sample_id` | 本项目样本号，`CUAD-001` 至 `CUAD-020`；不是官方编号 |
| `contract_title` | `CUADv1.json` 中的原始 `title`，保留大小写与 Unicode 字符，精确匹配 |
| `contract_type_hint` | 根据标题得到的类型提示，不是全文审核结论 |
| `source_file` | `CUADv1.json`，相对于同学自行解压的数据目录 |
| `source_split` | `train` 或 `test`，按官方合同归属记录 |
| `planned_use` | `development` 为开发候选；`evaluation_reserved` 为预留测试候选 |
| `context_chars` | 原始字符串字符数，含空白 |
| `context_sha256` | 原始 `context` 的 UTF-8 字节 SHA-256，用于防止拿错合同版本 |
| `change_of_control_spans` | 控制权变更条款的答案片段数 |
| `anti_assignment_spans` | 合同转让限制条款的答案片段数 |
| `termination_for_convenience_spans` | 无须违约事由的终止条款的答案片段数 |
| `cap_on_liability_spans` | 赔偿责任限制条款的答案片段数 |
| `uncapped_liability_spans` | 赔偿责任不设上限的条款的答案片段数 |
| `selection_reason` | 入选用途，包括类别覆盖或无答案对照 |
| `verification_status` | 数据结构、官方划分和位置检查状态；不表示人工签署或风险标签完成 |
| `notes` | 标题推定、共享片段、多片段和测试使用限制等具体说明 |

**取用流程：**从第 4 节下载数据 → 按 CSV 的 `contract_title` 查找完整数据 → 校验长度与 SHA-256 → 仅向系统提供合同原文和审查任务。评测程序另外读取 `qas` 标注。CSV 的五列片段数是参考信息，不能作为系统提前知道的答案。

在放有两份交付文件的目录，可用 Python 标准库复核清单。将 `data_dir` 改为官方数据解压目录即可，无须任何未提交的辅助脚本：

```python
import csv, hashlib, json
from pathlib import Path

data_dir = Path("CUAD")
docs = json.loads((data_dir / "CUADv1.json").read_text(encoding="utf-8"))["data"]
by_title = {d["title"]: d for d in docs}
with open("sample_manifest_draft.csv", encoding="utf-8-sig", newline="") as f:
    rows = list(csv.DictReader(f))
assert len(rows) == 20
assert len({r["contract_title"] for r in rows}) == 20
for r in rows:
    context = by_title[r["contract_title"]]["paragraphs"][0]["context"]
    assert len(context) == int(r["context_chars"])
    assert hashlib.sha256(context.encode("utf-8")).hexdigest() == r["context_sha256"]
print("20 份候选合同均可定位，长度与原文校验值一致")
```

## 9. 数据局限与适用范围

1. **语言与场景限制：**本轮使用英文商业合同，类型与时间跨度较大；结果不能直接推广到中文合同、特定行业或特定法域。并购情境是业务例子，不意味着所有合同都是并购协议。
2. **样本与长度偏差：**20 份候选按类别覆盖及长度筛选，超长文本和短文本未纳入，且官方类别本身不平衡。有限测试样本不足以证明生产环境可靠性或总体优劣。
3. **标注不等于风险：**CUAD 提供条款参考片段，不提供本项目统一的高、中、低风险标签。无答案标记和类别共享片段均需谨慎解释，规则与风险分级需要另设审核政策及人工参考判断。
4. **位置正确不等于语义充分：**全部位置检查通过，仅说明能找到相应原文；片段可能依赖定义、其他章节、附件或例外。原文 JSON 也不能保证附件完整，不据此宣称合同材料齐备。
5. **潜在数据泄漏：**保留合同级划分并排除精确重复，但主体前缀检查不能识别全部近似模板、关联企业或模型预训练中的数据接触。预留测试还经过覆盖筛选，应如实说明选样过程。
6. **时间与版本限制：**历史合同及政策不自动代表当前适用标准。审查应记录合同、政策及法律资料版本；法律时效或适用性不明时提示人工复核，首版不自动判断合同效力。
