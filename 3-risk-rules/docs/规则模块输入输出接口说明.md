# 风险规则模块输入输出说明

本模块负责风险规则和判断：接收识别答案及 5 号的证据核验结果，生成事实描述，执行适用规则并封装结果。每次处理一份合同的一个 CUAD 类别，对应总体流程第 6 步。推荐 4 号调用 `RuleTool.review()`；输入仍为原来的九个字段，不增加上游抽取负担。

## 一 共同输入字段

由 4 号汇总后传入：

| 字段 | 说明 | 来源 |
| --- | --- | --- |
| `document_id` | 合同标识，对应 CUAD title | 4 号任务初始化 |
| `question_id` | 当前类别的问题标识，对应 CUAD 问题 id | 4 号任务初始化 |
| `category` | 官方类别名称，见第二部分 | 4 号检查清单 |
| `category_answer` | 识别答案，字符串或 null | 4 号组织模型抽取 |
| `predicted_answers` | 引用原文列表，每项含 `text` 和 `answer_start` | 4 号组织抽取，并保留原文位置 |
| `evidence_checks` | 逐片段的核验结果，见下表 | 5 号证据核验 |
| `processing_status` | COMPLETED 已完成／INCOMPLETE 无法确认／ERROR 技术失败 | 4 号汇总上游识别状态 |
| `verification_status` | PASSED 通过／FAILED 失败／UNCERTAIN 无法确认 | 5 号汇总核验结果 |
| `coverage_status` | SUFFICIENT 充分／INSUFFICIENT 不足／NOT_APPLICABLE 不适用；No 尤其需要检查覆盖 | 5 号检查检索覆盖情况 |

### 引用与核验字段

| 字段 | 含义 |
| --- | --- |
| `predicted_answers[].text` | 引用原文 |
| `predicted_answers[].answer_start` | 引用在 5 号冻结的规范合同文本中的起始字符位置 |
| `evidence_checks[].answer_index` | 对应引用索引，从 0 开始 |
| `evidence_checks[].position_valid` | 位置是否有效：true／false／null |
| `evidence_checks[].support_status` | 是否支持答案：SUPPORTED／UNSUPPORTED／UNKNOWN |
| `evidence_checks[].reason` | 核验失败或无法确认的具体原因；通过时可为 null |

证据位置以冻结文本的 Unicode 码点为准；PDF 提取文本与 CUAD JSON 全文的偏移不能直接混用。证据检索与核验由 5 号负责，规则模块仅使用核验结果。合同全文、检索 question/query 和 top_k 不需传入本模块。

输入为系统自主识别结果，不是 CUAD 人工答案。未知答案填 null 并标记 INCOMPLETE，不把一次检索未命中直接当作 No。

## 二 五类条款分别提供什么

五个主题共用上述字段，仅 category 与 category_answer 的内容不同。正向答案附引用及核验结果；经充分覆盖检查的 No 可为空引用和空逐条核验列表，但整体核验必须通过且 coverage_status 必须为 SUFFICIENT。

### 1 适用法律

| 字段 | 内容 |
| --- | --- |
| `category` | Governing Law |
| `category_answer` | 地区名称，如 Illinois、California；复杂或联合答案保留完整含义 |
| `predicted_answers` | 支持地区答案的法律选择原文及位置 |

本模块配置 `allowed_governing_laws`（允许清单），执行 LAW-001。法院或仲裁地点不能替代适用法律；复杂答案无法可靠比较时返回无法确认。

### 2 续约与退出安排

| 字段 | 续约期限 | 退出通知期限 |
| --- | --- | --- |
| `category` | Renewal Term | Notice Period To Terminate Renewal |
| `category_answer` | 如 12 months、successive 1 year | 如 90 days、6 months |
| `predicted_answers` | 续约期限原文及位置 | 退出通知原文及位置 |

两类分别传入。续约期限执行 RENEWAL-001，按 `maximum_renewal_months` 比较明确单次期限，整数年按 12 个月归一化，不将天数换算为月。退出通知执行 NOTICE-001，使用 `notice_period_threshold_days` 和 `day_basis`：AS_WRITTEN_DAYS 按原文明示天数比较，CALENDAR 仅比较明确日历日。通知期限中的月、年和复杂窗口不默认换算，不据此推定通知主体或自动续约条件。

### 3 保险义务

| 字段 | 内容 |
| --- | --- |
| `category` | Insurance |
| `category_answer` | Yes／No；未知为 null |
| `predicted_answers` | 保险义务原文及位置 |

保留识别和核验结果，不额外要求险种、保额或受益信息。INS-001 在 `require_insurance_clause=true` 且答案为经过充分检查的 No 时触发；不判断保障是否充分。

### 4 审计权

| 字段 | 内容 |
| --- | --- |
| `category` | Audit Rights |
| `category_answer` | Yes／No；未知为 null |
| `predicted_answers` | 审计权原文及位置 |

保留识别和核验结果，不额外要求审计主体、频次、费用及通知条件。AUDIT-001 在 `require_audit_clause=true` 且答案为经过充分检查的 No 时触发；不推定权利归属本方。

### 5 无因终止

| 字段 | 内容 |
| --- | --- |
| `category` | Termination For Convenience |
| `category_answer` | Yes／No；未知为 null |
| `predicted_answers` | 无因终止原文及位置 |

保留识别和核验结果，不额外要求双方权利、通知期及补偿。TERM-001 在 `flag_if_present=true` 且答案为已核验的 Yes 时触发关注提示，不推定条款必然不利于本方。

## 三 输出字段

| 字段 | 说明 |
| --- | --- |
| 原九个输入字段 | 全部保留，不修改答案、引用或上游状态 |
| `fact_status` | CONFIRMED：输入及上游核验结论足以支持事实描述；UNCERTAIN：无法确认。不是新增的独立证据核验或 CUAD 评分 |
| `clause_description` | 按类别和核验状态生成的中文事实描述，不附加风险推断 |
| `rule_execution_status` | EXECUTED 已形成规则结果／DISABLED 规则关闭／NOT_CONFIGURED 未配置适用规则；EXECUTED 不代表触发或成功分级 |
| `review_results` | 规则判断列表；未配置或未启用适用规则时为空列表 |
| `requires_manual_review` | 顶层复核标志：事实无法确认或任一规则要求复核时为 true；不覆盖 Agent 其他节点的复核要求 |

`review()` 返回完整字典，4 号可直接加入合同报告的 `checks`。原 `evaluate()` 保留，只返回规则列表，适用于仅需要规则判断的调用；它不提供事实描述。不要把 `review()` 返回的整个字典放入 `review_results`。

### 六类事实描述

| 类别 | 已确认时的描述示例 |
| --- | --- |
| Governing Law | 识别到适用法律答案为：Illinois。 |
| Renewal Term | 识别到续约期限答案为：24 months。 |
| Notice Period To Terminate Renewal | 识别到退出续约通知期限答案为：90 days。 |
| Insurance | 存在保险义务条款。 |
| Audit Rights | 存在审计权条款。 |
| Termination For Convenience | 存在无因终止条款。 |

三类 Yes/No 的已确认 No 输出“经本次充分检查，未发现……条款”。答案未知或核验不足时输出“暂无法确认……”，同时保留上游原始答案作为待确认预测。关闭或不配置风险规则不影响事实描述。

事实可确认而政策无法判断时，允许 `fact_status=CONFIRMED` 且规则 `status=UNCERTAIN`，例如已核验的复杂续约答案不能可靠换算，或政策参数缺失。

每项 review_results 包含：

| 字段 | 说明 |
| --- | --- |
| `rule_id` | 规则编号：LAW-001、RENEWAL-001、NOTICE-001、INS-001、AUDIT-001 或 TERM-001 |
| `status` | TRIGGERED 触发／NOT_TRIGGERED 未触发／NOT_APPLICABLE 不适用／UNCERTAIN 无法确认 |
| `risk_level` | 仅触发且分级明确时输出配置的 HIGH／MEDIUM／LOW，否则 null |
| `reason` | 判断理由 |
| `evidence_indices` | 所依据引用的索引，与 predicted_answers 对应 |
| `missing_fields` | 缺失的识别信息或审核参数 |
| `requires_manual_review` | 是否需要人工复核 |
| `recommendation` | 补查或处理建议 |

六项规则输出 TRIGGERED／NOT_TRIGGERED／UNCERTAIN。保险、审计权的存在性要求或无因终止关注要求明确为 false，且输入有效时返回 NOT_APPLICABLE。`[]` 仅表示没有配置或没有启用适用规则，与已执行但未触发的 NOT_TRIGGERED 不同。

共识骨架中的 `level`、`missing_items` 分别对应这里的 `risk_level`、`missing_fields`。本说明给出供 4 号对齐的实现约定，尚不代表已完成真实 Agent 联调。

## 四 4 号调用与结果封装

```python
from rules import RuleTool

tool = RuleTool()
check = tool.review(
    document_id=extraction["document_id"],
    question_id=extraction["question_id"],
    category=extraction["category"],
    category_answer=extraction["category_answer"],
    predicted_answers=extraction["predicted_answers"],
    evidence_checks=verification["evidence_checks"],
    processing_status=extraction["processing_status"],
    verification_status=verification["verification_status"],
    coverage_status=verification["coverage_status"],
)
# 4号可再追加 retrieval_history、retry_count 等编排信息。
report["checks"].append(check)
```

六个约定类别均调用 `review()`，即使对应风险规则关闭；不要因上游核验失败而跳过描述封装。`review()` 自身负责保守输出无法确认及复核标志。新增五个合同基础信息类别仍由 Agent 封装，本入口不处理；传入其他类别会抛出 ValueError。

4 号反馈逻辑需检查 `fact_status`、上游状态、规则状态和顶层复核标志：

- 事实无法确认：根据原因先补查或重抽取，达到重试上限后转人工；即使规则关闭，也不能直接接受未确认事实。
- 事实已确认但规则无法判断：参数缺失应补配置，复杂业务含义应人工判断，不盲目重复检索。
- 规则已触发且要求人工复核：保留事实与风险提示并进入复核清单，不为消除风险提示而重试。
- 未触发、规则不适用或规则关闭：仍保留事实描述；没有其他异常时正常汇总。

## 五 反馈与判断边界

- 审核清单、阈值与等级由本模块配置，是模拟内部政策，不要求上游提供，也不等同于法律风险标准。
- 对已启用规则，输入不完整、证据未通过或参数缺失时返回 UNCERTAIN，并列出原因、缺项及建议；已确认满足不适用条件的情况可返回 NOT_APPLICABLE，不以信息缺失代替不适用。
- 4 号依据 processing_status、evidence_checks.reason、review_results 的状态和缺项安排补查，必要时转人工；本模块不执行检索、重试或证据核验。
- `review_results=[]` 不表示核验成功或合同无风险。即使该类别没有风险规则，4 号仍需检查识别状态和证据结果。
- 技术错误单独报告，不作为未触发。未启用政策时识别结果正常保留。

例如，退出通知答案为 90 days，核验通过，按 AS_WRITTEN_DAYS 与模拟阈值 60 比较，可返回触发及配置等级；不能进一步推断本方权利不公平。核验失败时返回无法确认，供 Agent 补查。
