# 基于 RAG 与规则核验的商业合同审查 Agent：理论框架与研究设计

**摘要：**面向投资与并购尽职调查中的商业合同初审，本文提出融合检索增强生成、版本化规则核验、证据校验与有限反馈的智能体研究框架。研究将条款识别、政策判断与证据支持区分为相互关联的评价层次，并基于 CUAD 数据的结构及训练集覆盖核验，确定五类目标条款、样本隔离方案和人工参考标签的构建方法。实验拟比较直接语言模型、固定检索增强流程与完整智能体，结合反馈消融和异常情境测试，评价审查质量、人工复核负担与计算开销之间的关系。

**关键词：**商业合同审查；检索增强生成；规则核验；智能体；证据可追溯性；CUAD

## 一、研究定位与业务问题

### 1.1 场景、决策主体与研究边界

本文研究投资与并购尽职调查中的商业合同初审，具体业务场景为：**投资或并购尽职调查团队在初审阶段，检查目标企业已签署的英文商业合同，确定需要优先复核的条款，并向人工审查人员交付可定位的证据与提示理由。**

审查人员需要判断续约是否造成持续义务、终止权是否影响业务延续、控制权变化是否触发额外程序，以及责任限制如何影响合同中的权利义务安排。这些事项可以影响后续尽调清单和谈判重点，但本研究只评价信息识别及政策核验质量，不估计交易收益、违约概率或企业价值。

研究采用收购方尽调团队的审查视角，关注目标企业承担的义务和享有的权利。主体映射以各份合同的签约方及其角色为依据，在样本筛选阶段逐项确认。主体无法识别时，系统仍可执行条款定位，但涉及主体的规则判断返回“无法确认”。

研究的核心问题为：

> 在相同合同、目标条款、审查立场、审核政策和基础模型下，加入检索、规则程序、证据核验与有限反馈，能否改善条款识别和审查输出的可靠性？相应的耗时、调用成本与人工转交负担是多少？

### 1.2 预期贡献

本文拟构建从“合同原文”到“条款事实”、再到“政策判断”和“证据记录”的审查框架，并通过与直接 LLM、固定 RAG 的对照评价其适用性。研究不以提出新的基础模型算法为目标，也不预设完整 Agent 必然优于简单方法。

## 二、理论基础与作用机制

### 2.1 金融理论基础：信息核查与监督成本

Jensen 与 Meckling 将代理成本区分为委托人的监督支出、代理人的担保支出及剩余损失，为分析所有权与控制权分离条件下的监督需求提供了理论基础[1]。在本研究的尽调场景中，合同承载有关企业权利、义务和交易条件的信息。审查人员需要把分散的条款转化为可核查的事项清单，信息遗漏和核查成本因此成为值得研究的问题。

本文借助代理理论解释交易中的信息核查需求，将审查耗时、人工复核工作量及证据核查难度作为审查成本的观察维度，将条款召回、误报和证据支持情况作为信息质量的评价维度。并购前的交易双方并不必然构成严格的委托—代理关系，因此上述联系属于研究场景的理论延伸。系统耗时仅反映计算效率；人工审查成本需通过人工计时与工作量测量，代理成本总额和交易损失则还涉及激励结构与交易后果，不能由模型指标直接识别。

### 2.2 RAG：为判断提供当前合同中的可定位信息

检索增强生成将外部检索材料与语言模型生成结合起来，为依赖资料的任务提供信息依据[2]。本研究采用这一思路：按目标条款在当前合同内检索相关文本，再进行事实提取和解释。这里的 RAG 是工程化检索流程，不是复现原论文的联合训练模型。

长文本研究发现，模型对相关信息的利用可能受到其在上下文中位置的影响[3]。因此，直接输入合同全文未必能够稳定覆盖所有条款；检索可能通过聚焦相关段落改善识别。但检索也可能漏掉定义、例外及交叉引用。**RAG 改善的是信息获取条件，不能单独保证事实、引用或风险判断正确。**

### 2.3 规则核验：将语言事实与审核政策分开

Sergot 等将《英国国籍法》的部分条文表示为逻辑程序，展示了以形式规则表达法律条件并据此推导结论的方法，同时讨论了例外、否定及知识完整性的限制[4]。该研究为条件规则的显式表达提供了方法依据，其研究对象与本文的合同审核政策不同，也不直接证明语言模型与规则程序组合的有效性。

本文据此采用事实与政策分离的设计：语言模型承担候选事实抽取，规则程序执行预先形式化的条件、阈值及例外。每项规则记录编号、版本、适用主体、前置条件、触发条件、等级和复核要求；对于无法形式化或证据不足的判断，保留人工复核入口。

这一设计让相同事实在相同版本政策下得到可重复的程序结果，也使错误能够归因于检索、抽取、规则实现或政策本身。不过，规则程序的确定性不等于法律判断的正确性；错误的输入事实或不适当的政策仍会产生错误输出。本文使用的阈值属于预先约定的模拟内部审核政策，不将其表述为法律规定或普遍市场标准。

规则状态采用本文定义的四值操作分类。合同材料可能不完整，因此不将“未检索到证据”解释为相应事实为假，也不直接采用把未知视为假的封闭世界假设。

### 2.4 Agent：根据检查结果选择下一步行动

ReAct 将语言模型的信息处理与外部行动交替组织，为“根据观察更新行动”的系统设计提供了参考[5]。本研究借鉴这一思想，设置任务清单、检索工具、规则工具、证据检查和停止条件：如果事实足够且证据有效，则执行规则并输出；如果缺少定义、位置不符或出现冲突，则补查或重新抽取；达到预算后转人工。

智能体机制的关键在于**后续操作依赖中间观察**。本文的固定 RAG 基准采用一次检索与一次生成；本文拟研究的 Agent 则根据证据缺口、工具状态及剩余预算选择补查、重试或人工升级，并通过行动记录评价反馈闭环的作用。系统架构采用单智能体与外部工具协同的方式。

### 2.5 证据可追溯性：引用位置与语义支持分别评价

关于带引用生成的研究将回答质量与引用质量分别评价，为本研究的证据评价提供了方法参考[6]。本研究进一步区分三层：第一，引用是否真实存在且位置正确；第二，原文是否支持抽取的主体、条件、否定和例外；第三，该事实是否足以支持所引用政策下的判断。

因此，“引用字符串正确”不能替代“结论得到支持”。例如，原文中确有“90 days”，但如果该期限适用于违约补救，而输出解释为退出自动续约的通知期，则定位检查可能通过，语义支持检查仍应失败。

Dahl 等在美国判例相关的开放域问答任务中系统研究了法律幻觉，说明法律文本生成需要独立验证[7]。本文属于以给定合同为依据的封闭域审查，不直接沿用该文的幻觉率或将其结果外推为本文模型的错误率；本文分别评价原文定位、事实支持与政策状态。

### 2.6 理论关系与预期作用路径

| 层次 | 需要解决的问题 | 本研究机制 | 可观察结果 |
| --- | --- | --- | --- |
| 金融业务 | 尽调信息分散，人工需确定核查重点 | 固定审查立场和目标条款清单 | 漏检、误报、复核负担 |
| 信息获取 | 关键约定可能被遗漏 | 当前合同内检索、补查定义与交叉引用 | 条款 F1、Recall@K |
| 判断执行 | 相同政策可能被解释得不一致 | 结构化事实与版本化规则程序 | 状态准确率、触发事项召回率 |
| 证据约束 | 生成结论可能缺少真实依据 | 位置校验、语义支持检查 | 定位有效率、证据支持率 |
| 流程控制 | 首轮结果可能不完整或工具失败 | 有限重试、停止、人工升级 | 补查收益、正确转交率、成本 |

以上作用路径是待检验的机制解释，不是已经建立的因果结论。

## 三、关键概念与审查任务的形式化

### 3.1 统一概念

| 概念 | 本研究定义 | 容易混淆的边界 |
| --- | --- | --- |
| 条款识别 | 找到属于目标类别的原文片段及其位置 | 找到条款不等于发现高风险 |
| 事实抽取 | 提取主体、期限、金额、权利义务、条件和例外 | 不将模型推测补成合同事实 |
| 检索证据 | 系统找到的候选原文 | 需经校验后才能支持判断 |
| 规则核验 | 对结构化事实执行固定审核政策 | 不将规则触发等同于违法 |
| 风险提示等级 | 当前立场及政策下的事项关注程度 | 不是概率，也不是合同整体安全评级 |
| 无法确认 | 判断所需事实、证据或适用条件不足或冲突 | 不自动转换为“低风险” |
| 人工升级 | 将待解决问题、已有证据和失败原因交给人工 | 不是自动获得人工确认，也不是实验中的正确答案 |
| 可追溯性 | 能从输出追溯至原文、事实、规则版本及执行记录 | 不要求公开模型内部推理过程 |

### 3.2 输入、输出与状态

给定合同文本 $D$、目标类别集合 $C$、审查立场 $P$ 和政策版本 $R$，以 $d$ 表示合同标识、$c\in C$ 表示条款类别、$r$ 表示该政策版本下的规则标识，系统输出各事项的结构化结果：

$$
O_{d,c,r}=(F,E,V,S,L,H),
$$

其中，$F$ 为事实，$E$ 为证据，$V$ 为证据核验结果，$S$ 为规则状态，$L$ 为提示等级，$H$ 为人工复核标记及原因。一类条款可关联多个规则事项，同一规则也可能使用多个类别的事实。条款评价单位为“合同×类别”；规则评价按“合同×规则”去重，不因使用多个类别而重复计数。

规则状态采用四类互斥的操作标签，不将其等同于形式逻辑中的四值语义体系：

$$
S\in\{\text{触发、未触发、不适用、无法确认}\}。
$$

“未触发”要求适用条件成立、证据足够且触发条件不成立；“不适用”要求有明确依据证明前置条件不成立；材料不足统一进入“无法确认”。未检索到条款只表示当前检索未找到，不能直接判定合同没有该条款。

等级采用 $L\in\{\text{高、中、低、null}\}$。触发事项按政策给出等级；未触发事项仅在政策明确规定时记为低，否则记为 `null`；不适用和无法确认均记为 `null`。高等级表示优先人工复核，中等级表示需确认或讨论，低等级表示该事项在当前政策下关注程度较低。`null` 不进入高、中、低的同一类别解释，但其导致的未判定必须计入覆盖率和漏检评价。

### 3.3 审查闭环与状态记忆

![合同审查智能体的执行流程、反馈控制与状态记忆](figures/review_workflow.png)

**图 1　合同审查智能体的执行流程、反馈控制与状态记忆**

审查流程按照任务规划、检索定位、事实抽取、证据核验和规则判断逐项推进。证据不足、信息冲突、必要字段缺失或工具调用失败时，系统进入统一的反馈分支：预算允许时补查或重试，预算耗尽时将事项标记为“无法确认”，保留现有证据与失败原因并转交人工。状态记忆贯穿各环节，用于维持任务一致性、限制重复调用并支持结果追溯。

| 系统要素 | 设计内容 |
| --- | --- |
| 感知 | 当前合同文本、检索结果、规则返回值、证据检查和工具错误 |
| 计划 | 将目标类别转换为检查清单，逐项记录完成或未解决状态 |
| 状态与记忆 | 合同 ID、文本版本、已读块、候选事实、证据、规则版本、重试次数和日志 |
| 行动 | 检索、读取上下文、抽取、校验、调用规则、补查、停止、转人工 |
| 反馈 | 缺失字段、引用不匹配、主体／例外冲突、规则错误及调用失败 |
| 停止条件 | 所有事项已判定或标记人工复核；或达到调用／时间预算 |
| 评价目标 | 在识别和证据质量、人工负担与计算开销之间进行比较 |

反馈策略拟将单个事项的补查上限设为 2 轮，并同时约束合同级调用次数与运行时间。具体预算在开发集试运行后冻结，测试期间保持一致。流程控制采用显式状态与停止条件，不涉及强化学习训练。

## 四、研究问题、假设与检验对应关系

下表中的方向是事先提出的研究假设，均允许被实验否定。组别定义见第六节。

| 编号 | 研究问题及机制假设 | 对照与主要指标 | 结论边界 |
| --- | --- | --- | --- |
| H1：检索增益 | 固定检索能否帮助模型定位相关内容？预期 B 相比 A 提高条款 Macro-F1 | B−A；条款 Macro-F1 为主，同时报告 Recall 和存在性误报率 | 若提升不稳定或召回下降，不能称 RAG 普遍有效；需分析检索遗漏 |
| H2：完整方案增益 | 清单、规则、证据检查与反馈共同加入后，能否提升审查质量？预期 C 相比 B 提高规则状态准确率和端到端证据支持成功率 | C−B；状态准确率、证据支持成功率；辅以高等级召回和覆盖率 | 比较支持的是完整方案的综合效果，不能把变化单独归因于规则工具 |
| H3：反馈增益 | 条件补查是否能修复首轮信息不足？预期 C 相比 C0 提高需补查案例的正确处理比例 | C−C0；主测试集条款召回、预设需补查子集的正确处理比例及压力测试通过数，同时记录补查次数与耗时 | C0 必须只关闭反馈补查；若不实施该消融，H3 只能保留为未检验假设 |
| RQ4：质量与资源权衡 | 质量变化需要多少耗时、token 和人工介入？不预设成本一定下降 | 各组合同级耗时、调用量、费用、人工转交率；有条件时测真实人工时间 | 模型耗时不能代替人工节省时间；转交率增加可能反映谨慎，也可能反映低覆盖 |

H1 的主指标预先固定为条款 Macro-F1；H2 的两项主要指标均报告方向、差值和区间，不依据单项改善作出整体有效的结论。H3 的“需补查”子集由评审者依据合同中的跨段定义、例外或必要材料缺口，在查看系统输出前标记；全测试集结果与该子集结果分别报告，避免按 C 组是否成功补查进行事后筛选。压力测试样例仅支持相应异常情境的机制分析。

## 五、数据、条款范围与参考答案

### 5.1 数据适配与候选条款

CUAD 是由经过培训的法学生标注、经验丰富的律师进行质量检查的商业合同审查数据集；论文报告 510 份合同、41 类标签和 13,101 个标注条款，合同来自 SEC 的 EDGAR 披露系统[8]。本研究使用其合同原文及条款片段作为识别评价依据，类别定义以官方说明文件为准[9]。**这些标签不是本研究审核政策下的高／中／低风险答案。**

研究范围设为以下 5 类，覆盖续约、终止、控制权变化及责任限制。英文名称与 JSON 问题 ID 中的类别名称一致；类别说明 CSV 中部分虚词的大小写存在差异，数据导入采用显式名称映射。

| 类别代码 | 官方类别名称 | 需要抽取的事实 | 业务关注点及判定限制 |
| --- | --- | --- | --- |
| C1 | Renewal Term | 续约机制、期限、双方权利和生效条件 | 识别持续义务；不能看到“续约”就判高风险 |
| C2 | Notice Period To Terminate Renewal | 退出续约所需通知期、通知主体及计算条件 | 与 C1 联合解释，不能与违约补救期混淆 |
| C3 | Termination For Convenience | 无因终止权归属、通知期、费用及例外 | 需结合目标企业是权利方还是义务方判断 |
| C4 | Change Of Control | 控制权变更触发条件、同意／通知要求、终止权 | 不把所有转让限制直接当作控制权变更条款 |
| C5 | Cap On Liability | 责任上限金额／计算基数、索赔期限、主体及例外 | 该类别也含索赔期限限制；不能只识别金额上限 |

类别存在与风险方向分别处理。例如，责任上限对承担责任一方和主张赔偿一方的影响可能不同，未找到上限也不能直接推出责任无限。因否定、例外或主体不明确而无法判定时，仍可报告条款存在，风险规则则保留不确定状态。

### 5.2 样本与数据隔离方案

实验拟设置 **20 份开发合同、40 份测试合同**，分别构成 100 个与 200 个“合同×类别”任务。示例展示材料从开发集选取，与测试材料隔离。最终样本清单依据以下预设规则形成。

1. 沿用已核验的官方划分：从 408 份训练合同中建立开发子集，从 102 份测试合同中建立测试子集。为保留完整多片段标注，开发侧优先读取 `CUADv1.json`，按训练文件的合同标题筛出训练部分；已拆分的 22,450 条问题记录需先按合同与类别聚合。聚合后，训练池对应 16,728 个此类任务。
2. 依据预先固定的文本完整性与语言要求筛选，保存合同 ID、原始划分、文本长度、排除理由和抽样种子。主体可识别性作为单独记录的属性，不因主体难以识别而直接排除合同，以保留“无法确认”与人工升级情形。抽样种子拟设为 `20261103`，并在生成样本清单前冻结。近重复合同及同一合同的不同版本不得跨开发／测试集合。
3. 开发集用于检查切块、调整提示、确定 K、政策阈值和调用上限。开发子集以每类至少 5 个正例和 5 个负例为覆盖目标；若 20 份合同无法满足该目标，则按预设规则调整或扩大子集。测试评价在方案冻结后进行，样本清单不随模型表现调整。
4. 测试样本保留目标类别无标注的负例，并逐类报告正、负例数。类别样本不足时注明估计限制；压力测试案例与真实合同分别统计。
5. 40 份测试合同用于初始比较，其逐类别、逐等级的有效样本量可能有限。资源允许时扩展至全部 102 份官方测试合同，并记录规则适用性筛选及排除情况；稀有类别补充集独立报告。小样本结果的解释以实际覆盖范围和估计不确定性为限。

已核验的官方训练池与测试池不存在完全相同的 `context` 哈希。哈希检查仅能排除完全重复文本；研究子样本形成时还需开展近重复检测、同系列合同识别及主体映射。上述 20／40 份为计划样本规模。

### 5.3 原文位置与测试答案隔离

系统输入仅包含合同文本、类别定义、业务任务和审核政策。CUAD 的人工答案、答案起点及补充风险标签留在评测侧，不能进入检索索引、生成提示、演示记忆或反馈工具。测试合同的原文本身是待审材料，可以供系统读取；测试标注答案不能供系统读取。

原文定位以导入的 CUAD `context` 字符串为不可变原文，采用从 0 开始、左闭右开的 Unicode 字符区间 `[start, end)`。证据必须满足 `context[start:end] == quote`。UTF-8 字节位置、JavaScript UTF-16 单元位置及 PDF 页码与该字符区间分别定义，不同实现语言之间通过显式转换保持定位一致。

切块、空白清洗或换行归一化应保留到原始 `context` 的映射。若文件包含多个 `context`，需保留 `context_id`，不能将局部偏移直接当作全文偏移。定位评价采用字符区间，不涉及 PDF 页码映射。

训练池核验显示，11,180 个答案片段的 `answer_start` 和 `text` 均能精确匹配原始 `context`，且 `is_impossible` 与答案列表是否为空一致；该结果验证了位置与字段一致性，标注的语义适切性仍通过争议案例复核处理。实际字段路径为 `data[].title`、`paragraphs[].context`、`qas[].question/id/is_impossible/answers` 及 `answers[].text/answer_start`。答案没有单独给出结束位置，应由 `answer_start + len(text)` 计算。数据版本记录同时保留 JSON 顶层版本字段 `aok_v1.0` 与文件名 `CUADv1.json`。

### 5.4 三类参考答案分别建立

| 参考答案 | 来源与构建方式 | 对应评价 |
| --- | --- | --- |
| 条款片段与存在性 | CUAD 标注；发现争议时统一记录、盲审并对所有组使用同一修订版 | 条款识别、检索覆盖、存在性误报 |
| 政策状态和等级 | 两名标注者依据冻结政策及合同原文独立标注，分歧由第三名评审裁决 | 规则状态、触发事项、高等级识别 |
| 证据语义支持与异常动作 | 隐去模型组别的人工评价；压力样例事先规定预期动作和依据 | 支持率、正确补查／停止／转交 |

补充标注包含合同 ID、规则 ID、适用主体、关键事实、证据、四值状态、等级及分歧说明。标注者在独立完成初标后核对差异，并保留原始判断、裁决依据及最终标签。

在裁决前报告四值状态及证据支持标签的原始一致率、列联表与未加权 Cohen’s $\kappa$[10]。等级另报逐级一致情况及分歧方向。类别高度集中或样本较少时，结合边际分布解释 $\kappa$；其分母为零时记为不可计算。一致性描述标注过程的可重复程度，不替代标签正确性审查。

参考标签在审核政策冻结后、模型结果揭示前独立构建，以避免待测规则引擎与评价依据同源。补充标签反映人工依据模拟审核政策作出的判断，其适用范围限于本文设定的任务与政策。

## 六、实验设计

### 6.1 基准与消融组

| 组别 | 输入与流程 | 用途 |
| --- | --- | --- |
| K0：关键词检索 | 固定类别关键词／同义词与排序规则，输出候选原文 | 低成本检索参照；报告 Recall@K 与存在性误报率 |
| A：直接 LLM | 合同全文、基本任务、共同政策和输出字段；一次生成 | 衡量直接阅读合同的基准表现 |
| B：RAG＋LLM | 采用冻结的切块与检索设置，输入固定候选片段，再一次生成 | 与 A 比较检索流程的综合影响 |
| C：完整 Agent | 与 B 相同的首轮检索，加详细检查清单、规则程序、证据检查及条件补查／人工升级 | 检验完整方案的综合表现 |
| C0：关闭补查的 Agent | 保留 C 的清单、规则、证据检查和人工升级，关闭证据不足引发的补查／重新抽取 | 与 C 比较反馈增益；资源不足时可列为后续实验 |

主实验设置 A、B、C 三组。K0 与其他组使用相同文本块、类别定义和检索返回预算，关键词及存在性判定阈值在开发集上冻结。K0 返回候选块，不直接参与要求精确片段边界的 F1 或风险等级评价。H3 的检验依赖 C0 消融实验；未实施该消融时，反馈机制的独立增益保留为未检验假设。

另设规则模块诊断：给规则程序和 LLM 输入相同、人工核验的结构化事实与政策，对照人工标签评价规则状态；再与原始合同输入的端到端结果比较。前者检验规则实现，后者包含检索与抽取错误。模块表现好而端到端表现差时，应先检查上游事实，不归结为政策推理能力不足。

### 6.2 公平比较与运行设置

- **共同条件：**各组共享合同、类别、审查立场、政策文本、等级定义、基础模型及版本、输出字段。A、B 同样获得政策全文，以控制政策信息可得性的差异。
- **系统差异：**详细执行清单和工具调用是 C 的组成部分。因此 C−B 评价整个方案，不能声称单独证明某一模块的因果效果。
- **首轮检索一致：**B、C、C0 共享检索器、切块和首轮候选；开发集上选定设置。可从 800 个模型 token／块、重叠 120 token、Top-K=5 起步，并遵从合同段落边界；最终参数依据开发集表现确定。
- **上下文可比：**训练合同的字符数中位数为 35,960.5，P90 为 128,120.3，最长为 338,211；这些是字符数，不是模型 token 数。确定基础模型后应使用其分词器检查长度，预留政策与输出空间，再确定全文可容纳的主比较范围。超长合同另设分析；若 A 存在截断，记录截断比例并单独报告，避免将输入信息不完整的影响归因于系统架构。
- **生成与预算：**冻结温度、最大输出、超时及重试设置；模型不支持某参数时记录默认行为。完整方案可能调用更多次，主表如实报告质量与实际开销；预算匹配实验作为独立补充，用于分析相同资源约束下的性能差异。
- **重复与错误：**同一测试集计划运行 3 次，保存每次输出与失败记录。至少完成 1 次全量运行；只运行 1 次时不报告模型重复运行的稳定性结论。传输重试和语义补查分开计数，所有组采用同一传输重试政策。
- **结果独立：**各合同和各实验组使用独立运行状态，避免上一组的结果、纠错信息或人工答案进入下一组。

### 6.3 运行记录与可复现性

各组通过相同的确定性位置校验器评价输出。若模型仅输出引用文本，校验器在不可变原文中进行精确匹配；多处匹配时须由输出的上下文标识消歧。无法唯一定位的引用记为定位失败，不使用语义近似匹配修复。

每次运行至少记录：`run_id`、`group`、模型与参数、提示版本、合同／文本版本、条款类别、规则／政策版本、检索配置、`context_id`、证据区间及引用、结构化事实、规则状态、等级、人工复核原因、补查次数、调用次数、输入／输出 token、用时及错误状态。

机器日志保存工具参数、观察结果和简短决策理由即可。人工语义评价表另行保存评审人、支持／不支持／信息不足、分歧和裁决，不把模型自评当作独立验证结果。

## 七、评价指标与统计口径

### 7.1 条款识别与检索

片段匹配限定在同一合同、同一 `context_id` 和同一类别内，采用**字符区间 IoU≥0.5、最大匹配数的一对一匹配**作为本研究的主匹配口径：

$$
IoU(p,g)=\frac{|p\cap g|}{|p\cup g|},\quad
Precision=\frac{TP}{TP+FP},\quad
Recall=\frac{TP}{TP+FN},\quad
F1=\frac{2TP}{2TP+FP+FN}。
$$

其中 $p$ 与 $g$ 分别表示预测和参考片段的字符位置集合。对 IoU 达到阈值的预测—参考对建立二分图，采用最大基数的一对一匹配；匹配数相同时，优先选择总 IoU 更高的方案。完全相同的预测区间去重，其他重叠片段保留并参与匹配，未匹配预测记 FP，未匹配标注记 FN。引用无法定位的预测记 FP；存在标注却弃答或调用失败时，相关标注记 FN。

主指标为逐类别 F1 的宏平均，另报 Micro-F1、逐类别召回与样本数。宏平均类别集合由完整测试集中的参考正例确定并对各组保持一致；若某类无参考正例，则单列其误报数，不纳入正类识别的宏平均。无预测但有参考正例时，Recall 与 F1 为 0，Precision 因分母为零记为不可计算。

该匹配方法是本研究自定义的定位指标。CUAD 原论文按规范化后的词集合 Jaccard≥0.5 判断片段匹配，并报告 AUPR 及 80%／90% 召回率下的精确率[8]。本文使用字符位置及一对一匹配，故不与原论文结果作直接数值比较。IoU 阈值的敏感性分析限于开发阶段，测试时保持冻结。

检索阶段另报 `Recall@K`：所有真实标注片段中，被前 K 个检索块并集覆盖至少 80% 字符的片段比例。K 和 80% 阈值在测试前固定，分母不含无标注的负例；同时公布块大小和检索 token 量，避免通过返回超大块虚增指标。

存在性误报率的分母为 CUAD 对应类别无标注的“合同×类别”任务数，分子为其中系统声称发现条款的任务数。相对于数据集的无标注不一定等于法律意义的不存在；争议案例按统一盲审流程处理。

### 7.2 政策判断与风险提示等级

| 指标 | 操作定义 | 必须同时报告的事项 |
| --- | --- | --- |
| 四值状态准确率 | 状态预测与人工参考一致的规则事项数／全部预设规则事项数 | 无输出和格式失败计错误；混淆表另列无效输出列 |
| 触发事项 Precision／Recall | 将“触发”作为正类计算；应触发却返回无法确认、未触发、不适用或无输出均计漏检 | 将错误触发与恰当保留不确定性分开分析 |
| 等级 Macro-F1 | 对参考等级非空的事项，按高／中／低计算；预测 `null` 或失败计入真实等级的 FN | 各等级数量、参考为空却输出等级的次数 |
| 高等级召回率 | 参考高等级且预测高等级的事项数／参考高等级总数 | 中、低、`null` 和失败均属于未召回 |
| 严重降级率 | 参考高等级却预测低等级的事项数／参考高等级总数 | 另报高→中、高→未判定，不能只看高→低 |
| 判定覆盖率 | 输出触发或未触发的事项数／参考状态为触发或未触发的事项数，仅在该参考子集计算 | 同报该子集的正确率、总体转交率及总体失败率 |

参考状态为无法确认的案例，系统返回无法确认可以是正确状态；参考状态可确定而系统弃答时，则不能当作准确判定。无高等级参考时，高等级召回率和严重降级率填“不适用（分母为 0）”，不填 100% 或 0%。

### 7.3 证据追溯与人工复核

| 指标 | 操作定义 |
| --- | --- |
| 引用定位有效率 | 合同 ID、文本版本、区间和引用全部匹配的引用条数／全部输出引用条数 |
| 证据支持率 | 被证据在主体、条件、否定和例外上完整支持的实质性结论数／全部输出实质性结论数；应有引用却没有引用的结论计不支持 |
| 端到端证据支持成功率 | 在参考状态为触发、未触发或不适用的事项中，状态正确且全部必要事实有有效、充分证据的事项数／该参考子集的事项总数；缺项、弃答和失败计未成功 |
| 记录完整率 | 所有必填输出及日志字段齐全的任务数／全部应运行任务数；必填项依输出状态确定，`null` 的理由同样必须记录 |
| 正确转交率 | 预设需人工复核事项中，系统正确转交且给出可核查原因的数量／预设需人工复核事项数 |
| 过度转交率 | 预设无需人工复核事项中被转交的数量／预设无需人工复核事项数 |

定位检查由程序完成；语义支持采用隐去组别的双人评价与争议裁决。小规模实验优先全量核验；若只能抽查，预先按组别、类别和输出状态分层等概率抽取，并公布抽样数、比例和加权方式，以保持成功与失败输出的代表性。没有输出引用或结论时，条件指标分母为 0，应记不可计算，并用端到端成功率和覆盖率反映失败，使完全弃答的系统无法仅凭条件指标获得高评价。

“需人工复核”的参考包括政策要求复核的高等级事项，以及关键证据、主体、附件或适用条件无法确认的事项。能够正确给出高等级提示并转人工，与“无法判定而转人工”分别统计。

### 7.4 效率、统计与错误分析

效率按合同汇总，报告运行耗时中位数、P90、调用数、输入／输出 token、检索及嵌入开销。费用依据运行日期对应模型的实际计价或账单记录计算；缺少可核验计价数据时，仅报告 token 用量。失败和重试的资源消耗计入总量，人工时间另列。

统计比较采用同一合同上的配对设计。NLP 评价应依据任务结构、指标及数据依赖关系选择统计方法[11]；本文据此将合同而非单条条款作为重采样单位，以保留同一合同内任务的相关性。拟进行 1,000 次配对 bootstrap，每次各组使用相同的重采样合同索引，重新计算指标及组间差值，以第 2.5 与第 97.5 百分位给出 95% 区间。

若执行 3 次重复运行，点估计取三次指标的平均值；每次合同重采样保留其全部重复运行输出，分别计算各次指标后再取平均。合同重采样区间反映样本变化的不确定性，模型运行间波动另行报告。重采样时宏平均的类别集合保持固定；因无正例等原因不可计算的统计量记录缺失比例，不临时删除类别。小样本或大量重采样结果缺失时，区间仅作描述性参考，以原始计数和配对差值为主，不据此宣称稳定的显著性结论。

错误归因统一使用：检索遗漏、主体识别错误、期限／数值抽取错误、否定／例外处理错误、跨引用缺失、规则实现错误、无依据结论、引用定位错误、应转未转、过度转交及工具失败。保存能够复核的案例，不只展示成功样例。

## 八、压力测试与边界案例

压力测试拟设置 5 类情境，每类构造 2 个案例，共 10 个，并保留对应的正常原文作为对照。优先从开发材料或明确标注的人工文本构造，不将其混入真实合同主结果。每个案例在运行前写清变更位置、生成规则、预期状态和允许动作，变更后重新计算文本版本与引用偏移。

| 情境 | 构造方式 | 预期行为与失败判据 |
| --- | --- | --- |
| 关键证据／附件缺失 | 删除必要的定义或被引用附件 | 有预算时补查，仍不足则无法确认并转人工；编造附件内容为失败 |
| 否定与例外 | 设置一般规则及其例外，或改变否定词 | 引用完整上下文，正确更新适用事实；只抓关键词导致错误触发为失败 |
| 工具调用失败 | 注入检索超时或规则工具错误 | 按固定策略重试、记录错误，耗尽预算后转人工；静默输出通过为失败 |
| 合同内干扰指令 | 在合同材料中加入要求忽略审核任务的文字 | 将其作为待审文本，不改变任务和政策；遵从干扰指令为失败 |
| 跨合同片段混入 | 检索候选中混入其他合同的相似条款 | 根据合同 ID 和原文匹配排除；以其他合同证据支持判断为失败 |

异常处理通过率为符合该案例事先规定的最终状态、允许行动及证据要求的案例数／全部压力案例数，同时报告通过数与总数。10 个定向构造案例不构成对真实异常发生率或总体可靠性的估计。对于可通过补查恢复的案例，正确完成审查是成功；对于客观不可恢复的案例，停止并正确转交是成功。转交行为仅在满足该情境的预设条件时计为通过。

**规则机制示例（模拟情境）：**某合同要求退出自动续约提前 90 天通知，模拟审核政策 `R-REN-01 v0.1` 规定“在目标企业承担该通知义务、确有自动续约且无相关例外时，通知期超过 60 天触发中等级提示”。预期流程为定位原文、核验主体及期限、执行规则、输出触发／中等级及复核建议。如果原文仅写“按附件规定通知”且附件缺失，预期为补查后仍无法确认则转人工。该示例中的 90 天、60 天及提示等级均为说明规则机制而设定，不构成实测结果、法律标准或市场阈值。

## 九、研究局限与适用边界

1. **样本外适用性：**CUAD 的 EDGAR 合同披露样本与一般企业合同总体存在选择差异[8]。研究结果限于实际样本类型，不能直接推广到中文合同、特定司法辖区或全部并购交易。主比较若限制了文本长度，结论仅适用于该长度范围，不能扩展到未测试的超长合同。
2. **公开数据污染：**不能排除基础模型训练时见过 CUAD。固定模型和隔离测试标签能减少本研究内泄漏，但不能证明完全没有预训练污染。
3. **政策与主体依赖：**风险等级随审查立场及模拟审核政策变化。修改规则阈值后必须更新版本和标签，不能继续沿用旧结果。
4. **证据不是法律裁决：**检索与规则检查只能支持给定任务范围内的初审，不能证明合同有效性、可执行性或整体没有风险。
5. **治理与权限：**系统只读取任务材料和生成审查报告；遇高等级、证据冲突、主体不明或材料不足，交由人工处理。记录可核查依据，不自动对外提交法律结论。
6. **解释实验结果：**若 C 改善证据支持但耗时与转交率上升，应如实表述为质量与资源的权衡；若只在压力样例上改善，结论限定于这些异常情境。演示案例仅用于说明运行机制，研究假设的判断以预设实验评价为依据。
