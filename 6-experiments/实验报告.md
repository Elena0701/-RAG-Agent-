# 对比实验报告

# 一、实验目的

本实验旨在评估"基于 RAG 与规则校验的混合 Agent"在企业合同审核任务中的实际效果，重点考察引入知识检索、规则校验与多阶段工作流后，对合同条款识别准确性、完整性与综合性能的影响，并通过与单次大语言模型调用方式的对比，分析不同技术路线在条款识别任务中的表现差异。

合同文本通常篇幅较长、专业术语较多、条款表达形式复杂且关键信息分散。传统人工审查需要逐份阅读并定位相关条款，工作量较大，且容易受到审查人员经验与注意力的影响。大语言模型具备一定的自然语言理解与信息提取能力，可用于辅助合同条款识别，但在处理长篇合同和多类别识别任务时，仍可能出现条款遗漏、语义混淆以及证据定位不准确等问题。

针对上述问题，本实验构建了基于检索增强与多阶段处理机制的合同条款识别 Agent，并将其与单次调用大语言模型的方法进行对比。在相同的合同数据、条款类别和 CUAD 人工标注结果下，比较两种方法的召回率、精准率和 F1 值，以分析 Agent 在合同条款识别任务中的实际效果及其存在的局限。

# 二、实验设计

## （一）实验基本思路

本实验所考察的 Agent 面向商业合同尽职调查中的初审场景，采用"检索—抽取—核验—规则判断—补查或人工复核"的闭环处理流程：Agent 控制器负责组织任务，RAG 工具完成合同解析、分块以及语义与关键词混合检索，内部大语言模型抽取条款答案和逐字引文，规则工具依据已配置政策检查触发状态；证据核验包括位置核验、语义核验与否定覆盖检查，核验未通过时进入有限补查，无法确认的事项则转入人工复核清单。系统支持 41 类条款识别，并输出可追溯的原文依据与复核清单。

为比较 Agent 与传统单次大模型调用方式的差异，本实验同时设置单次大语言模型组和 Agent 组，并采用 GPT-4.1 作为基线模型。Agent 组具备审查 41 类条款的能力，本次对比实验聚焦其中的 11 类，通过候选文本检索、类别识别和证据核验等环节，将合同条款识别任务拆分为多个相互衔接的处理步骤，以提高识别结果的准确性与可靠性。单次大模型组对每份合同仅发起一次模型请求，将合同全文一次性输入模型，并要求模型在同一次回答中完成 11 类合同条款的识别。

与单次大模型识别方法相比，本实验中的 Agent 方法主要具有以下优势：

- 引入 RAG 检索机制：针对不同条款类别开展针对性检索，缩小信息范围，提高相关条款的定位能力，降低无关信息对识别结果的干扰。
- 采用多阶段任务处理流程：将识别任务拆分为候选检索、信息提取与结果核验等环节，逐步推进，避免单次整体判断可能造成的遗漏。
- 引入独立风险政策规则：结合预设的风险政策规则，对识别出的条款进一步审查，增强对潜在合同风险的识别与提示能力。
- 支持分类针对性识别：按条款类别分别检索与分析，使识别过程更加聚焦，有助于提升复杂合同中关键条款的识别效果。
- 强化证据核验机制：要求识别结果提供对应的合同原文依据，并通过独立核验检查证据的相关性与有效性，提高结果的可追溯性和可信度。

## （二）实验数据与识别任务

本实验选取 CUAD 测试集中的 102 份合同文本作为实验数据，所有合同均以 TXT 文本形式输入系统，以保证两种识别方法基于相同的文本进行判断。出于实验时间与成本的考虑，对比实验选用 CUAD 数据集中的 11 类合同条款作为识别对象，具体见表 1。

**表 1 条款编号、类别名称与识别内容**

| 条款编号 | 类别名称（英文）                           | 识别内容     |
| ---- | ---------------------------------- | -------- |
| Q1   | Document Name                      | 合同名称     |
| Q2   | Parties                            | 合同当事方    |
| Q3   | Agreement Date                     | 合同日期     |
| Q4   | Effective Date                     | 生效日期     |
| Q5   | Expiration Date                    | 到期日期     |
| Q6   | Renewal Term                       | 续约期限     |
| Q7   | Notice Period To Terminate Renewal | 终止续约通知期限 |
| Q8   | Governing Law                      | 适用法律     |
| Q16  | Termination for Convenience        | 无因终止条款   |
| Q34  | Audit Rights                       | 审计权条款    |
| Q39  | Insurance                          | 保险义务     |

每份合同均需针对上述 11 类条款分别判断，因此实验共包含 102 × 11 = 1122 个合同—条款判断样本。实验采用 CUAD 提供的人工标注结果作为真实标签（Ground Truth）：对于每一个合同与条款类别的组合，标注为 1 表示存在对应条款，标注为 0 表示不存在。系统识别结果也统一转换为 0 或 1，以便与人工标注结果逐项比较。

## （三）实验评价指标

本实验以 CUAD 人工标注结果为真实标签、系统输出结果为预测标签，构建二分类混淆矩阵。各符号含义如下：

- TP（True Positive，真正例）：标注为 1、预测也为 1，表示真实存在的条款被正确识别。
- FP（False Positive，假正例）：标注为 0、预测为 1，表示实际不存在的条款被错误识别。
- FN（False Negative，假负例）：标注为 1、预测为 0，表示实际存在的条款未被识别。
- TN（True Negative，真负例）：标注为 0、预测也为 0，表示实际不存在的条款被正确判断。

在此基础上，采用召回率、精准率和 F1 值评价模型的识别效果。

### 1. 召回率（Recall）

召回率衡量模型识别出全部真实存在条款的能力，召回率越高，说明遗漏的真实条款越少。计算公式为：

Recall = TP / (TP + FN)

### 2. 精准率（Precision）

精准率衡量模型识别为存在的条款中实际正确的比例，精准率越高，错误识别不存在条款的情况越少。计算公式为：

Precision = TP / (TP + FP)

### 3. F1 值（F1-score）

F1 值是精准率与召回率的调和平均数，用于综合评价识别性能，F1 值越高，说明模型在准确性与完整性之间取得了更好的平衡。计算公式为：

F1 = 2 × Precision × Recall / (Precision + Recall)

# 三、实验数据分析

## （一）对比实验

基于上述 1122 个合同—条款判断样本，实验分别运行 Agent 识别方法和 GPT-4.1 单次识别方法，并将两种方法的预测结果与 CUAD 人工标注结果逐项比较。混淆矩阵计数与各项评价指标见表 2。

**表 2 Agent 与 GPT-4.1 单次识别方法的混淆矩阵与评价指标**

| 统计指标 | Agent               | GPT-4.1 单次识别        |
| ---- | ------------------- | ------------------- |
| TP   | 543                 | 518                 |
| FP   | 29                  | 35                  |
| FN   | 126                 | 151                 |
| TN   | 424                 | 418                 |
| 样本总数 | 1122                | 1122                |
| 召回率  | 0.811659193（81.17%） | 0.774289985（77.43%） |
| 精准率  | 0.949300699（94.93%） | 0.936708861（93.67%） |
| F1 值 | 0.875100725（87.51%） | 0.847790507（84.78%） |

从整体计数看，在相同样本下，Agent 正确识别出的真实条款为 543 个，高于单次大语言模型的 518 个；错误识别为 29 个，低于对方的 35 个；漏检为 126 个，也低于对方的 151 个。这表明 Agent 不仅在正确识别真实条款方面结果更多，在减少错误识别和遗漏真实条款方面同样具有一定优势。

在召回率方面，Agent 为 81.17%，单次大语言模型为 77.43%，高出约 3.74 个百分点。结合混淆矩阵可知，Agent 的 FN 为 126 个，比单次识别方法少遗漏 25 个真实条款，说明其在条款信息定位和识别覆盖方面表现更好。

在精准率方面，Agent 为 94.93%，单次大语言模型为 93.67%，高出约 1.26 个百分点。Agent 的 FP 为 29 个，低于单次识别方法的 35 个，说明其将实际不存在的条款误判为存在的情况更少。

在综合指标 F1 值方面，Agent 达到 87.51%，单次大语言模型为 84.78%，高出约 2.73 个百分点。由于 F1 值同时兼顾召回率与精准率，这一结果说明 Agent 在提高真实条款识别覆盖率的同时，仍然保持了较高的预测准确性，在两项指标之间取得了更好的平衡。

总体而言，在本实验设置下，Agent 在召回率、精准率和 F1 值三个方面均优于 GPT-4.1 单次识别方法，表明检索增强、多阶段任务处理和证据核验等机制对合同条款识别具有积极作用。

## （二）Agent 漏检情况及局限性分析

尽管 Agent 在整体识别效果上优于单次大语言模型，实验结果也反映出其仍存在一定局限：Agent 的假负例（FN）达到 126 个，即 CUAD 标注为存在、但 Agent 最终未识别为存在的样本。

从漏检分布看，Agent 在处理到期日期（Q5，58 例）、生效日期（Q4，26 例）和合同日期（Q3，16 例）等日期类条款时最容易出现漏检，三类合计 100 例、约占全部漏检的 79.4%，说明在这些条款的检索与识别方面仍需重点加强。各类条款的漏检数量分布见图 1。

结合 Agent 的系统处理流程，漏检问题可能主要与以下几个方面有关。

第一，候选条款检索阶段可能存在召回不足。Agent 依靠检索机制定位与目标类别相关的合同文本，但检索结果未必覆盖合同中的全部相关内容。若真实存在的条款未进入候选文本范围，后续模型便难以作出正确判断，检索阶段的遗漏会直接传递到识别环节，形成最终的 FN。

第二，合同条款表达具有较强的多样性。同一类合同权利或义务可能采用不同措辞，部分条款并不直接使用对应类别的关键词。例如，某些合同可能以较为间接的语言描述审计权限、保险维持义务或无因终止权。若检索与识别过度依赖关键词或常见表达形式，就可能遗漏采用特殊措辞的真实条款。

第三，部分条款需要结合多个段落综合判断。合同中的关键信息可能分布在不同章节：权利内容在一个段落中说明，适用条件、通知期限或相关义务则在其他段落中规定。如果系统主要依据局部候选文本作出判断，可能因无法充分整合分散信息而低估条款的完整性。

第四，严格的证据要求可能增加边界样本的漏检风险。Agent 在识别过程中需要提供原文证据并进行核验，当合同表述复杂、证据不够直接或相关内容存在歧义时，系统可能无法充分确认条款成立，从而未输出正确的存在判断。这一机制有助于控制误识别，但也可能使部分真实存在、表达间接的条款未被识别。

综上，126 个 FN 反映出 Agent 目前仍存在候选条款召回不足、复杂语义识别能力有限、跨段落信息整合不充分以及严格证据核验可能造成边界样本遗漏等问题。后续可从以下方面改进：一是优化候选条款检索策略，提高不同表达形式下相关文本的召回能力；二是扩展同义表达与语义匹配范围，减少对固定关键词的依赖；三是加强跨段落信息关联与上下文整合；四是进一步优化证据核验机制，在保证证据可靠性的同时，减少因表达形式差异造成的漏检。

# 四、实验结论

本实验基于 102 份合同文本，选取 CUAD 数据集中的 11 类条款作为识别对象，构建 1122 个合同—条款判断样本，并以 CUAD 人工标注结果为真实标签，对基于检索增强和多阶段处理机制的 Agent 与 GPT-4.1 单次大模型识别方法进行了对比。

实验结果表明，在本次数据集和实验条件下，采用检索增强、多阶段处理及证据核验机制的 Agent，相较于直接对合同全文进行单次判断的大语言模型，具有更好的条款识别综合性能：召回率、精准率和 F1 值分别达到 81.17%、94.93% 和 87.51%，均高于单次识别方法。这说明将长篇合同识别任务拆分为候选信息检索、类别判断与证据核验等环节，有助于改善模型对合同条款的定位和识别效果。

与此同时，实验也发现 Agent 仍存在 126 个假负例，表明其在真实条款的全面覆盖方面仍有不足，尤其是在日期类条款、非典型表达、关键信息分散以及复杂上下文关联等情形下，仍可能出现漏检。后续优化应重点放在提高候选条款检索召回率、增强复杂语义理解能力、完善跨段落信息整合机制以及改进证据核验策略等方面。

综上，本实验验证了 Agent 在当前合同条款识别任务中的应用价值。与单次大语言模型调用相比，Agent 在本次实验中取得了更高的召回率、精准率和 F1 值，体现出多阶段智能体架构在复杂合同文本处理任务中的一定优势；但其识别效果仍受到检索质量与复杂语义处理能力的影响，后续仍需通过进一步优化和更细致的类别级实验分析，提高系统对合同条款的识别完整性与稳定性。
