# 36 类审查政策文字化说明

## 1 审查目标与政策依据

本模块服务于IPO尽调中的商业合同初筛，以发行人为分析对象，为受托律师及券商尽调团队提供条款事实、原文证据和风险提示。人工结合主体、条件、例外及业务背景评估实际影响。

类别及答案口径依据 [01类别与模式总表](01类别与模式总表.md)。政策按信息展示、条件触发关注、要求存在、关联复核四种模式组织；适用范围、参数和等级由本地配置明确。

风险等级字段为 `risk_level`，取HIGH／MEDIUM／LOW，表示本次政策下的初筛提示，辅助安排复核顺序。信息不足作为独立状态保留，实际法律和业务判断由人工完成。

## 2 共用输入与处理要求

### 2.1 输入与事实确认

合同层使用 `document_id`，每个类别项包含 `question_id`、`category`、`category_answer`、`predicted_answers`、`evidence_checks`、`processing_status`、`verification_status`、`coverage_status`。必要事实使用现有答案及证据；额外的主体、金额和豁免细节作为人工阅读内容。

| 输入情况 | 处理要求 |
| --- | --- |
| 地区／期限答案或Yes | 抽取完成、整体核验通过，相关引用位置和语义支持通过，引用与检查索引对应 |
| No | 抽取完成、整体核验通过且coverage_status为SUFFICIENT；引用可以为空 |
| null、未完成、技术错误、核验失败、覆盖不足或字段缺项 | 保留原始答案和状态，描述为无法确认，说明缺项并安排补查或复核 |
| 片段截断、定义或交叉引用影响含义 | 上游补充完整证据并核验，待核查项保留无法确认 |

每个已选类别均传入一项，未选类别不处理。批量外层结构有效时，各项独立执行，按输入顺序保留成功及异常结果。证据核验由5号负责，补查由Agent组织。

### 2.2 政策结果

| 结果 | 含义 |
| --- | --- |
| TRIGGERED | 适用政策的触发条件满足，输出配置的风险等级及复核要求 |
| NOT_TRIGGERED | 已完成政策判断且条件未满足，风险等级为空 |
| NOT_APPLICABLE | 政策明确不适用，或其具体要求明确关闭，风险等级为空 |
| UNCERTAIN | 已启用政策所需事实、证据或参数不足，等级为空，列明原因 |
| 未配置／未启用规则 | 保留事实描述和证据，风险结果为空 |

信息展示只输出事实，关联复核另附阅读提示和复核要求。两者风险等级为空。已启用的分级政策须具备完整参数，缺失时按无法确认处理。

事实状态与政策结果分别保存。例如已核验的 `until terminated` 可原样展示，其月数阈值比较结果为无法确认。规则关闭也保留事实描述，技术错误继续保留ERROR。

## 3 条件触发关注：地区及期限 3 类

### 6．Renewal Term｜续约期限（RENEWAL-001）

| 要素 | 政策说明 |
| --- | --- |
| 必要事实 | 明确的单次续约期限及支持该答案的引用和核验结果 |
| 本地参数 | 规则开关、是否适用、单次续约月数上限、风险等级、触发后复核要求 |
| 触发／未触发 | 可比较月数严格大于上限则触发；小于或等于上限未触发 |
| 例外与边界 | 整数年按12个月归一化；successive 1 year按单次12个月比较，条件和不定期期限转人工。 |
| 信息不足 | 上限缺失、答案为空，以及天数、范围、分档、条件性或不定期期限无法可靠比较时，返回无法确认。 |
| 人工复核 | 超限且配置要求复核，或复杂期限、证据冲突、商业接受程度需要判断时复核 |

演示：上限为 12 个月时，24 months 触发，1 year 未触发，until terminated 的政策比较无法确认。参数由本次演示政策配置。

### 7．Notice Period To Terminate Renewal｜退出续约通知期限（NOTICE-001）

| 要素 | 政策说明 |
| --- | --- |
| 必要事实 | 明确的退出续约提前通知期限及支持该答案的引用和核验结果 |
| 本地参数 | 规则开关、是否适用、通知天数上限、天数口径、风险等级、触发后复核要求 |
| 触发／未触发 | 同口径明确天数严格大于上限则触发；小于或等于上限未触发 |
| 例外与边界 | AS_WRITTEN_DAYS 按明示天数比较且保留原单位；CALENDAR 仅接受明确日历日。不将工作日换算为日历日，不把续约时长、违约补救或无因终止通知当作本类别 |
| 信息不足 | 月年、复杂窗口、多个期限冲突、未明确日历日但政策要求日历日、参数缺失或核验不足时无法确认；不计算缺少到期日依据的截止日期 |
| 人工复核 | 超限且配置要求，或期限含义、适用条件需要进一步解释时复核 |

演示：上限 60 天时，90 days 触发，60 days 未触发；上限调整至 90 天后，同一 90 days 未触发。6 months 不默认转换为 180 天。

### 8．Governing Law｜适用法律（LAW-001）

| 要素 | 政策说明 |
| --- | --- |
| 必要事实 | 明确的适用法律地区答案及支持该答案的引用和核验结果 |
| 本地参数 | 规则开关、是否适用、非空允许清单、明确别名、风险等级及触发后复核要求 |
| 触发／未触发 | 能可靠规范化的地区不在清单内则触发；匹配清单则未触发 |
| 例外与边界 | 不用管辖法院或仲裁地点代替法律选择；别名只做等价名称映射，不删除例外或国家／地区限定 |
| 信息不足 | 多法律、事项例外、联合或条件答案不能可靠匹配，或清单缺失、别名配置无效时无法确认 |
| 人工复核 | 清单外且配置要求，或复杂适用关系、法域含义需要解释时复核；清单内也不代表法律安排已全面审查 |

演示：允许 California 和 New York 时，Illinois 触发；提示说明该答案未满足本次允许清单。

## 4 条件触发关注：存在性 20 类

以下每类共用必要事实为其 Yes/No 答案及第 2 节要求的核验状态。政策参数为规则开关、是否适用、发现时是否提示、触发等级及触发后复核要求。

**统一条件：**政策启用、明确适用且开启发现提示时，已核验 Yes 触发；充分检查的 No 未触发。发现提示明确关闭或政策明确不适用时不适用；开关、适用性或等级等必要参数未确定则无法确认。未知或核验不足不当作 No。

触发后按配置安排人工复核，下表给出各类关注事项及阅读重点。条件、豁免及对发行人的实际影响由人工结合原文确认。

| CUAD 编号 | 官方类别 | 触发时的关注事项 | 人工复核重点 |
| --- | --- | --- | --- |
| 9 | Most Favored Nation | 存在最惠待遇安排，按政策关注 | 确认受益方、比较对象和适用条件。 |
| 10 | Non-Compete | 存在竞业限制安排，按政策关注 | 确认限制主体、地域、业务范围、期间及同意例外。 |
| 11 | Exclusivity | 存在排他性安排，按政策关注 | 确认排他方向、期间及允许的合作或交易。 |
| 12 | No-Solicit Of Customers | 存在客户招揽或交易限制，按政策关注 | 确认受限客户、交易行为、适用期间和例外。 |
| 14 | No-Solicit Of Employees | 存在员工招揽／招聘限制，按政策关注 | 确认限制对象、期间，以及公开招聘或主动应聘等例外。 |
| 15 | Non-Disparagement | 存在禁止贬损安排，按政策关注 | 确认适用主体、言论范围及相关例外。 |
| 16 | Termination For Convenience | 存在无因终止安排，按政策关注 | 确认权利方、通知、费用及对发行人的影响。 |
| 17 | Rofr/Rofo/Rofn | 存在优先购买／要约／谈判类权利，按政策关注 | 确认具体权利种类、持有人、标的和行使程序。 |
| 18 | Change Of Control | 存在控制权变更相关安排，按政策关注 | 确认控制权变更定义、同意／通知／终止安排及豁免。 |
| 19 | Anti-Assignment | 存在转让限制，按政策关注 | 确认转让条件、通知、同意及允许转让范围。 |
| 20 | Revenue/Profit Sharing | 存在收入／利润分享安排，按政策关注 | 确认分成方向、计算基数和支付条件；本轮使用存在性答案。 |
| 21 | Price Restrictions | 存在定价或调价限制，按政策关注 | 确认定价或调价限制的方向、频次、幅度及例外。 |
| 22 | Minimum Commitment | 存在最低采购／交易承诺，按政策关注 | 确认最低金额／数量、周期及未达标后果；本轮使用存在性答案。 |
| 23 | Volume Restriction | 存在使用量／数量限制，按政策关注 | 确认使用阈值、超额收费、同意条件及其他后果。 |
| 27 | Non-Transferable License | 存在许可转移限制，按政策关注 | 确认受限许可及允许转移情形。 |
| 31 | Irrevocable Or Perpetual License | 存在不可撤销或永久许可，按政策关注 | 区分不可撤销与永久许可，确认受益方、期限和适用范围。 |
| 33 | Post-Termination Services | 存在合同终止后义务，按政策关注 | 确认过渡、支付、移交、收尾等终止后义务及持续期间。 |
| 35 | Uncapped Liability | 存在无上限责任相关安排，按政策关注 | 确认责任主体、违约类型及上限例外。 |
| 37 | Liquidated Damages | 存在约定损害赔偿或终止费用，按政策关注 | 确认赔偿或终止费用的触发事件、支付条件及金额。 |
| 40 | Covenant Not To Sue | 存在不起诉／不争议承诺，按政策关注 | 确认受限请求、知识产权争议及救济范围。 |

案例：某类政策开启发现提示，Yes 且核验通过则触发；同类 No 且覆盖充分则未触发；No 覆盖不足、Yes 无引用或必要政策缺失则无法确认。风险等级由配置提供。

## 5 要求存在：3 类

共用必要事实为该类别的Yes/No答案及第2节核验状态。适用性和存在性要求由本地选定政策明确。

选定政策分别明确三类要求的适用范围；适用性未确定时，保留事实并提示核对政策。

**统一条件：**事实明确、政策启用且明确适用，并明确要求该条款时，充分检查的 No 触发，已核验 Yes 未触发；政策明确不适用或明确不要求存在则不适用。适用性未知、要求未设、No 覆盖不足或必要配置缺失时无法确认，不将未知布尔参数按 false 处理。

触发时按配置输出风险等级及复核要求，人工进一步核对业务豁免和合同外安排。

| CUAD 编号 | 官方类别 | 必要的政策适用前提 | 人工复核重点 |
| --- | --- | --- | --- |
| 32 | Source Code Escrow | 本次明确选定的软件许可／技术服务采购政策要求源代码托管 | 在明确适用的软件政策下检查存在性，进一步复核代码范围和释放条件。 |
| 34 | Audit Rights | 本次选定政策要求合同包含审计权条款 | 在适用政策下检查存在性，进一步确认权利主体、对象和权限。 |
| 39 | Insurance | 本次选定政策要求合同包含保险义务条款 | 在适用政策下检查存在性，进一步复核主体、险种、保额及期间。 |

案例：明确适用并要求源代码托管，No 且覆盖充分则触发；同样 No 但政策适用性未知则无法确认；政策明确不适用则不适用。仅出现保险一词但无支持义务含义的上游核验结论，不足以确认 Yes。

## 6 信息展示：5 类

以下类别共用必要事实为 Yes/No 答案及第 2 节核验状态，不额外要求定量信息。事实确认后，Yes 描述存在，No 描述“经本次充分检查，未发现”，未知或核验不足描述无法确认。

**统一政策：**输出事实描述、证据及核验状态，风险结果和等级为空。事实明确时正常汇总，事实无法确认时列入复核。

| CUAD 编号 | 官方类别 | 事实描述对象 | 人工阅读重点 |
| --- | --- | --- | --- |
| 26 | License Grant | 是否存在许可授予相关条款 | 展示授予事实；授权范围、权利链及业务适配性由人工进一步审查。 |
| 28 | Affiliate License-Licensor | 是否存在涉及许可方关联企业或其知识产权的许可条款 | 结合许可方关联企业定义、知识产权定义与实际授予条款。 |
| 29 | Affiliate License-Licensee | 是否存在涉及被许可方关联企业的许可条款 | 确认被许可方关联企业范围及相应授权条件。 |
| 30 | Unlimited/All-You-Can-Eat-License | 是否存在无限使用许可相关条款 | 确认无限使用范围及用途、地域、用户等限定；注意模板选项。 |
| 38 | Warranty Duration | 是否存在保修期限相关条款 | 按总表Yes/No描述保修期限相关条款，原文中的具体期限供人工阅读。 |

案例：License Grant 为已核验 Yes，则描述存在，风险结果为空，不输出等级；同项核验失败则描述无法确认。Warranty Duration按Yes/No输出，具体保修天数保留在原文中供人工阅读。

## 7 关联复核：5 类

共用必要事实为Yes/No答案及第2节核验状态。政策配置关联提示开关、阅读方向和复核要求。

**统一政策：**已核验Yes且提示开启时，输出事实及关联阅读提示，标记人工复核，风险等级为空。充分检查的No描述本次未发现；提示关闭时展示事实。信息或核验不足时返回无法确认及复核原因。

关联提示按单类别生成，保留该类别的事实状态；人工结合相关条款进一步解释。

| CUAD 编号 | 官方类别 | 人工关联阅读内容 | 人工确认要点 |
| --- | --- | --- | --- |
| 13 | Competitive Restriction Exception | 结合 Non-Compete、Exclusivity、No-Solicit Of Customers 的限制范围、同意和豁免安排 | 结合竞业、排他性和客户招揽条款，确认例外适用范围。 |
| 24 | Ip Ownership Assignment | 核查知识产权转移方向、标的、保留权利，以及 License Grant、Joint Ip Ownership 等相关安排 | 确认转移方向、标的、保留权利及相关许可。 |
| 25 | Joint Ip Ownership | 结合成果定义、归属转移、许可和使用／处分规则 | 结合共有份额、成果定义和使用、收益及处分安排。 |
| 36 | Cap On Liability | 结合 Uncapped Liability、责任类型、金额／索赔期限及例外 | 结合金额上限、索赔时间限制、无上限责任及适用例外。 |
| 41 | Third Party Beneficiary | 核查具体非签约受益人、可执行的权利及其对应义务 | 确认非签约受益人、可执行权利及对应义务。 |

案例：Cap On Liability 为已核验 Yes，则展示责任限制事实、提示结合无上限责任及例外人工阅读，风险等级为空；即使同批 Uncapped Liability 也为 Yes，也不直接输出“条款矛盾”或 HIGH。


## 8 复核与反馈

| 事项 | 后续动作 |
| --- | --- |
| 事实或证据不足 | Agent按原因补查，达到预算或涉及解释时转人工 |
| 事实明确、政策缺项 | 补充配置或人工明确适用条件 |
| 命中风险政策 | 保留风险提示，按配置进入复核清单 |
| 关联提示 | 人工结合相关条款确认范围和实际影响 |
| 信息展示或规则关闭 | 保留事实、证据及核验状态，汇总到报告 |

各项结果汇总人工复核标志，原始识别和技术状态完整保留。

## 9 政策来源与验证

CUAD问题定义及归一化答案用于确定识别目标，原文与位置用于证据核查。政策通过存在性判断、清单匹配和期限比较生成风险提示。外部 [合同审查清单与示例](https://github.com/evolsb/claude-legal-skill) 用于补充角色意识、关注理由及人工阅读维度。

每条政策记录来源、适用场景、选择理由和判断边界。数值建议经明确口径和人工确认后纳入配置；本文件中的12个月、60天及允许清单为演示政策参数。

按文字条件为36类编写正常、否定、未知及例外案例，并开展回归检查。CUAD标注用于识别和证据评价，冻结政策及独立预期结果用于评价政策执行一致性。
