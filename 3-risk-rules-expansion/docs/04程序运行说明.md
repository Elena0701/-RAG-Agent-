# 程序运行说明

## 1 环境与文件

在 `3-risk-rules-expansion` 目录运行，使用Python 3.10及以上版本，仅依赖标准库。已有FinAI环境可直接激活：

```powershell
conda activate FinAI
```

需要新建环境时执行 `conda env create -f environment.yml`。

| 文件 | 作用 |
| --- | --- |
| rules/rule_engine.py | 单类别处理、批量调用、事实描述及结果封装 |
| rules/validation.py | 输入格式、上游处理状态和逐条核验结果检查 |
| rules/policy_checks.py | 政策参数检查、存在性判断、清单匹配和期限比较 |
| rules/rule_tool.py、rules/__init__.py | 对外导入入口 |
| rules/__main__.py | 从JSON文件读取批量输入并保存结果 |
| rules/category_registry.json | 36类答案类型和事实描述模板 |
| rules/risk_rules.yaml | 政策、参数、风险等级和复核要求 |

## 2 批量调用

以下示例模拟上游已完成抽取和核验，展示批量接口的用法。

```python
import json
from rules import RuleTool

quote = "Either party may prevent renewal by giving 90 days' written notice."
payload = {
    "document_id": "DEMO_CONTRACT",
    "items": [{
        "question_id": "DEMO_CONTRACT__Notice Period To Terminate Renewal",
        "category": "Notice Period To Terminate Renewal",
        "category_answer": "90 days",
        "predicted_answers": [{"text": quote, "answer_start": 0}],
        "evidence_checks": [{
            "answer_index": 0,
            "position_valid": True,
            "support_status": "SUPPORTED",
            "reason": "模拟上游核验通过",
        }],
        "processing_status": "COMPLETED",
        "verification_status": "PASSED",
        "coverage_status": "NOT_APPLICABLE",
    }],
}
tool = RuleTool()
report = tool.review_batch(**payload)
print(json.dumps(report, ensure_ascii=False, indent=2))
```

向items增加其他类别项即可批量处理，每类保留独立答案和核验状态。本例默认政策为通知上限60天，结果包含90 days事实描述、TRIGGERED、MEDIUM和人工复核要求。

## 3 文件调用

将批量输入保存为UTF-8 JSON，顶层使用document_id和items：

```powershell
python -m rules input.json --output result.json
```

指定另一份政策配置：

```powershell
python -m rules input.json --policy custom_policy.yaml --output result.json
```

省略output时打印结果。政策文件采用JSON语法的YAML子集，修改后重新创建RuleTool实例。也可在代码中使用 `RuleTool(config=load_config("custom_policy.yaml"))`；load_config从rules导入。

## 4 返回与反馈

结果顶层为document_id和results，每项按item_index对应输入。各项保留答案、引用和状态，增加事实描述、模式、风险判断、关联提示、问题原因和人工复核标志，字段定义见 [批量接口说明](03统一配置与批量接口说明.md)。

| 情况 | 输出 |
| --- | --- |
| 信息展示 | 事实描述；风险和关联列表为空 |
| 命中风险条件 | review_results包含TRIGGERED及配置等级 |
| 要求存在且明确适用 | 充分检查的No触发，Yes未触发 |
| 要求存在但适用性待确认 | 保留已确认事实，政策为UNCERTAIN，issues说明需明确applicable |
| 关联复核 | 已核验Yes生成context_review_notes，风险列表为空 |
| 上游未完成或核验失败 | 事实无法确认，保留原因和复核要求 |
| 单项缺项、类别错误或重复 | 本项为ERROR，后续项继续，输出条数和顺序保持一致 |

保险、审计权和源代码托管的默认适用性为待确认。按本合同选定政策设置后再进行确定性缺失判断。

## 5 单项入口

`review()` 接收document_id和当前类别的八个字段，返回包含document_id的完整单项结果；`evaluate()`仅返回其中的分级风险判断列表。批量入口将document_id统一置于顶层。

单类别函数用于独立调用；4号进行合同级汇总时使用review_batch。构造器检查类别注册及全局配置，批量外层输入错误抛出ValueError，单项问题保留在本项结果中。

## 6 本地验证

执行 `python -m tests.run_tests` 运行自动化测试并保存逐用例结果；也可执行 `python -m unittest discover -s tests -v`。覆盖范围与最近执行结果见 [自动化测试说明与结果](05自动化测试说明与结果.md)。测试文件及模拟数据保留在本地tests目录。
