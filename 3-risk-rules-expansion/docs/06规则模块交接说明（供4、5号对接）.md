# 规则模块交接说明

## 1 对接目标与职责

规则模块面向IPO尽调中的商业合同初筛，接收同一合同选定的n类结构化结果，返回各类事实描述、政策判断、风险等级及人工复核要求。支持CUAD的36个非基础信息类别；合同名称、当事方及三个日期类别由Agent展示。

| 负责人 | 工作与交付 |
| --- | --- |
| 3号：风险规则与审核标准 | 提供类别清单、政策配置和可调用规则程序；执行规则，返回事实描述、风险结果及复核要求 |
| 4号：Agent程序搭建 | 确定审查类别，调度检索、抽取和核验；汇总批量输入，调用规则模块；接收结果，安排补查、人工复核和报告展示 |
| 5号：检索与证据核验 | 接收合同原文、类别和检索query；返回相关原文、位置、逐条证据核验及本类别覆盖状态 |

类别答案由大模型依据检索证据抽取，具体抽取步骤的实现归属由4／5号确认。规则模块使用上游核验结论，检查输入格式及状态是否满足政策判断要求。

```text
4号：选定n类，调度检索与抽取
                  ↓
5号：检索、定位及核验证据，说明覆盖情况
                  ↓
4号：汇总类别答案与核验结果 → 调用规则模块
                  ↓
3号模块：逐类描述事实、执行政策 → 一次返回n类结果
                  ↓
4号：根据结果补查、转人工或展示报告
```

## 2 传给规则模块的输入

顶层共用`document_id`，`items`中每个类别一项。只传本次选定类别；选定类别暂时无法确认时，也保留该项并填写未知状态。

| 字段 | 含义与取值 | 汇总来源 |
| --- | --- | --- |
| `document_id` | 当前合同ID，非空字符串，批量层共用 | 4号任务信息 |
| `items[].question_id` | 当前合同与类别的任务标识 | 4号生成／关联 |
| `items[].category` | CUAD官方类别名，须与注册表完全一致 | 4号审查任务 |
| `items[].category_answer` | 33类为字符串`Yes`／`No`；适用法律、续约期限及退出续约通知期为非空字符串；未知为`null` | 抽取结果 |
| `items[].predicted_answers` | 引用列表：`[{text, answer_start}]`；无引用为`[]` | 原文抽取及5号定位 |
| `items[].evidence_checks` | 逐条核验列表：`[{answer_index, position_valid, support_status, reason}]` | 5号核验结果 |
| `items[].processing_status` | `COMPLETED`／`INCOMPLETE`／`ERROR` | 4号汇总处理状态 |
| `items[].verification_status` | `PASSED`／`FAILED`／`UNCERTAIN` | 5号核验结果，经4号汇总 |
| `items[].coverage_status` | `SUFFICIENT`／`INSUFFICIENT`／`NOT_APPLICABLE` | 5号覆盖检查结果 |

引用位置基于同一份冻结合同文本，以从0开始的Unicode码点计数。`answer_index`从0开始，对应本项`predicted_answers`，每条引用提供一条核验记录。`position_valid`为`true`／`false`／`null`；`support_status`为`SUPPORTED`／`UNSUPPORTED`／`UNKNOWN`；`reason`为说明字符串或`null`。

**未发现与无法确认的填写方式：**

| 情况 | 填写要求 |
| --- | --- |
| 已确认存在或已抽取明确值 | 提供答案、原文引用及通过的逐条核验；处理完成、核验通过；覆盖状态可为`NOT_APPLICABLE` |
| 充分检查后未发现某Yes／No类别 | 答案为`No`，引用和逐条核验均为`[]`；处理完成、核验通过、覆盖为`SUFFICIENT` |
| 仅未检索到候选，检查尚不充分 | 答案为`null`，保留实际处理／核验状态，覆盖为`INSUFFICIENT`；不得直接按`No`处理 |

适用法律与两个期限类别未取得可靠答案时使用`null`。未选类别不传入，也不视为缺失。每项均需包含八个字段，未知值使用对应的`null`、空列表或状态值。

## 3 调用方式与输入示例

运行目录为`3-risk-rules-expansion`，使用Python 3.10及以上版本，仅依赖标准库。

```python
import json
from rules import RuleTool

payload = json.loads(open("input.json", encoding="utf-8").read())
tool = RuleTool()
result = tool.review_batch(**payload)
```

文件方式调用：

```powershell
conda activate FinAI
python -m rules input.json --output result.json
```

以下输入模拟上游已确认退出续约通知期为90天，证据位置基于仅包含该句的模拟文本。真实联调时使用实际原文位置与核验结果。

```json
{
  "document_id": "DEMO_01",
  "items": [{
    "question_id": "DEMO_01__Notice Period To Terminate Renewal",
    "category": "Notice Period To Terminate Renewal",
    "category_answer": "90 days",
    "predicted_answers": [{
      "text": "Either party may prevent renewal by giving ninety (90) days prior written notice.",
      "answer_start": 0
    }],
    "evidence_checks": [{
      "answer_index": 0,
      "position_valid": true,
      "support_status": "SUPPORTED",
      "reason": "模拟上游核验通过"
    }],
    "processing_status": "COMPLETED",
    "verification_status": "PASSED",
    "coverage_status": "NOT_APPLICABLE"
  }]
}
```

增加类别时，向`items`添加独立对象即可。外层无效输入抛出`ValueError`；单项异常记录在该项结果中，其他项继续处理。输出项数与顺序保持一致，重复类别的后续项返回错误。

## 4 返回结果与Agent使用方式

顶层返回`document_id`和`results`。每项保留八个原始输入字段，并增加：

| 输出字段 | 内容与用途 |
| --- | --- |
| `item_index` | 对应输入顺序，从0开始；结合`question_id`关联任务 |
| `fact_status`、`clause_description` | `CONFIRMED`／`UNCERTAIN`及本类事实描述，用于报告展示 |
| `mode`、`rule_execution_status` | 处理模式及执行状态，用于区分已执行、展示、关联复核、关闭或错误等情况 |
| `review_results` | 风险判断列表：规则ID、判断状态、风险等级、理由、证据索引、缺项、复核要求及建议 |
| `context_review_notes` | 关联复核列表：规则ID、需结合的类别、阅读重点、证据索引及复核要求 |
| `requires_manual_review` | 本类别是否要求人工复核 |
| `issues` | 输入、上游状态或政策问题的代码、说明及相关字段，供Agent安排补查或修正 |

`review_results[].status`为`TRIGGERED`／`NOT_TRIGGERED`／`NOT_APPLICABLE`／`UNCERTAIN`。仅`TRIGGERED`输出配置的`risk_level`（`HIGH`／`MEDIUM`／`LOW`），其余为`null`。`evidence_indices`指向本项保留的引用列表。

| 模式 | 返回行为 |
| --- | --- |
| 信息展示 | 输出事实与核验状态，风险和关联提示列表为空 |
| 条件触发关注 | 经核验的答案满足政策条件时返回风险提示 |
| 要求存在 | 政策明确适用且要求存在时，充分检查后的`No`触发提示 |
| 关联复核 | 经核验的`Yes`生成关联阅读提示，风险判断列表为空 |

上例使用默认60天通知上限，返回“识别到退出续约通知期限答案为：90 days。”、`TRIGGERED`、`MEDIUM`及人工复核要求。`UNCERTAIN`应展示原因并安排补查或人工判断；`NOT_TRIGGERED`表示本项政策未触发。

## 5 政策与首次联调

政策位于`rules/risk_rules.yaml`，由3号维护。通知上限、法律清单、模式、风险等级及复核要求均可配置，运行前固定本次使用的政策。保险、审计权及源代码托管的默认适用性为待确认，按合同场景明确后再判断确定的缺失风险。修改配置后重新创建`RuleTool`实例。

首次选一份真实合同，传入**适用法律、退出续约通知期、保险**三项结果：

1. 4／5号确认类别答案的抽取归属、原文冻结方式、覆盖充分的判定口径及状态汇总方式。
2. 4号提供一份上述格式的真实批量JSON；5号提供对应证据与核验说明；3号明确本次政策，运行并返回完整结果。
3. 共同确认三项结果均可关联原任务、追溯引用，并能正确展示事实、风险及补查／复核要求；记录字段和状态上的差异。
