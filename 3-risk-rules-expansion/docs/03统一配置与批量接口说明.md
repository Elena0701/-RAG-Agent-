# 统一配置与批量接口说明

## 1 配置文件

| 文件 | 内容 |
| --- | --- |
| [category_registry.json](../rules/category_registry.json) | 36类官方名称、中文名称、答案类型和事实描述模板 |
| [risk_rules.yaml](../rules/risk_rules.yaml) | 审查场景、四种模式、适用性、条件参数、风险等级、复核要求及来源 |

类别信息与政策分别维护。政策以官方类别名为键，每类通过rule_id标识对应规则或展示项目。`risk_rules.yaml` 采用JSON语法书写，属于YAML子集，可由Python标准库读取。

程序按本说明实现，调用示例见 [程序运行说明](04程序运行说明.md)。

## 2 类别注册

| 字段 | 内容 |
| --- | --- |
| `cuad_index` | CUAD完整41类中的序号 |
| `category` | 官方类别名，用于输入匹配 |
| `label` | 中文名称 |
| `answer_type` | BOOLEAN、DURATION或JURISDICTION |
| `fact_templates` | BOOLEAN使用present／absent／unknown；其他类型使用value／unknown |

BOOLEAN接受字符串Yes／No，未知为null；DURATION和JURISDICTION接受非空字符串，未知为null。事实描述复述核验支持的答案，保留复杂表达。模板中的 `{value}` 填入识别答案。

## 3 政策结构

### 3.1 共用字段

每类政策位于 `policies[官方类别名]`。

| 字段 | 含义 |
| --- | --- |
| `rule_id` | 规则或展示项目的标识 |
| `mode` | 本类别采用的处理模式 |
| `enabled` | 是否执行本类政策；false时仍展示事实 |
| `applicable` | true明确适用、false明确不适用、null待确认 |
| `condition_type` | 条件触发模式使用的判断类型；其他模式为null |
| `parameters` | 本模式需要的参数对象 |
| `risk_level` | 风险触发后的HIGH／MEDIUM／LOW；信息展示和关联复核为null |
| `manual_review_on_trigger` | 风险触发后是否要求人工复核 |
| `manual_review_on_context` | 关联提示命中后是否要求人工复核 |
| `review_note` | 触发后或关联提示中的人工阅读重点 |
| `applicability_note` | 政策适用范围说明 |
| `source_ids` | 对应顶层sources中的来源标识 |
| `rationale` | 本项政策的选择理由 |

`review_context` 记录IPO初筛、发行人及使用团队；`sources` 记录项目政策、CUAD定义和补充审查清单。来源记录服务于政策说明，运行判断使用明确配置的条件。

### 3.2 四种模式与参数

| 模式 | condition_type | parameters | 执行规则 |
| --- | --- | --- | --- |
| INFORMATION_ONLY 信息展示 | null | 空对象 | 输出事实和核验状态，风险结果及等级为空 |
| FLAG_IF_CONDITION 条件触发关注 | ANSWER_IS_YES | flag_if_present | true时已核验Yes触发，充分检查的No未触发；false时本要求不适用 |
| FLAG_IF_CONDITION 条件触发关注 | LAW_NOT_IN_ALLOWLIST | allowed_governing_laws、law_aliases | 明确地区不在允许清单内触发 |
| FLAG_IF_CONDITION 条件触发关注 | DURATION_MONTHS_GT | maximum_renewal_months | 明确单次续约月数严格大于上限触发 |
| FLAG_IF_CONDITION 条件触发关注 | NOTICE_DAYS_GT | notice_period_threshold_days、day_basis | 同口径明确通知天数严格大于上限触发 |
| REQUIRE_PRESENT 要求存在 | null | require_present | applicable和require_present均为true时，充分检查的No触发，Yes未触发 |
| CONTEXT_REVIEW 关联复核 | null | related_categories | 已核验Yes时生成关联提示，按配置标记复核；No只描述事实 |

BOOLEAN可采用四种模式；地区及期限类型采用信息展示或与类型相容的条件触发。修改模式时同时调整condition_type、parameters、风险等级和复核字段。

所有阈值为非负数，续约月数采用整数。续约中的整数年按12个月归一化，复杂表达返回无法确认。通知期限采用AS_WRITTEN_DAYS或CALENDAR口径，按文字政策处理单位。

事实满足处理要求后，applicable为false时跳过该项政策判断：风险模式返回NOT_APPLICABLE，关联模式不生成业务关联提示，事实继续保留。require_present或flag_if_present明确为false时，本要求直接返回NOT_APPLICABLE。其余情况下applicable为null时，已启用的风险或关联政策等待明确适用性，输出缺项及复核要求。信息展示仅描述事实。

### 3.3 当前演示政策

- 适用法律、退出通知、保险、源代码托管、控制权变更及无上限责任的分级政策使用MEDIUM，其余分级政策使用LOW；信息展示和关联复核的风险等级为空。
- 续约上限12个月、退出通知上限60天，适用法律清单为California／New York。
- 保险、审计权、源代码托管的require_present为true，applicable为null；选定对应合同政策后将applicable明确为true或false。适用性未确定时，不生成确定的缺失风险结论。
- 分级政策触发后的人工复核开关为true，关联提示复核开关为true；信息展示不因展示本身要求复核。

这些数值和等级属于本项目的初筛演示配置。每次实验固定所用配置，实际使用按合同政策调整并重新加载。

### 3.4 固定处理要求

顶层processing中的四项均为true：信息不足要求复核，No要求充分覆盖，关闭政策仍保留事实，批量输出保持输入顺序。这些是接口和证据处理要求，配置无效时应报告配置错误。

## 4 修改示例

将退出通知上限从60天改为90天：

```json
"Notice Period To Terminate Renewal": {
  "parameters": {
    "notice_period_threshold_days": 90,
    "day_basis": "AS_WRITTEN_DAYS"
  }
}
```

以上仅展示需修改的局部，文件中的其他字段保留。相同90 days答案在60天政策下触发，在90天政策下未触发。

若选定的软件合同政策明确要求源代码托管，将该类applicable设为true；若明确不适用则设为false。关闭整个检查使用enabled=false。三者分别表示启用并适用、启用但不适用、未启用。

## 5 批量输入

批量入口设计为 `review_batch(document_id, items)`，单类别 `review()` 负责逐项处理。items只包含本次选定类别，每类一项。

```text
document_id
items
  ├─ question_id
  ├─ category
  ├─ category_answer
  ├─ predicted_answers: [{text, answer_start}]
  ├─ evidence_checks: [{answer_index, position_valid, support_status, reason}]
  ├─ processing_status
  ├─ verification_status
  └─ coverage_status
```

输入值继续使用COMPLETED／INCOMPLETE／ERROR、PASSED／FAILED／UNCERTAIN、SUFFICIENT／INSUFFICIENT／NOT_APPLICABLE，以及逐条核验的SUPPORTED／UNSUPPORTED／UNKNOWN。位置以冻结合同文本的Unicode码点为准。

文档标识须为非空字符串，items须为非空列表；这类外层错误抛出ValueError。列表中的单项格式错误、缺项或不支持的类别只影响本项。重复类别保留首项，后续重复项返回异常结果，输出项数和顺序保持不变。

## 6 批量输出

顶层返回 `document_id` 和 `results`。results每项保留该项八个输入字段，并增加下列内容。单类别入口包含document_id，批量入口将其统一置于顶层。

| 字段 | 含义 |
| --- | --- |
| `item_index` | 对应输入列表的索引，从0开始 |
| `fact_status` | CONFIRMED或UNCERTAIN，依据输入及上游核验结论 |
| `clause_description` | 本类事实描述；未知或核验不足时描述为无法确认 |
| `mode` | 实际采用模式；未配置政策时按信息展示处理，类别无法识别时为null |
| `rule_execution_status` | 见下表 |
| `review_results` | 分级风险政策判断列表 |
| `context_review_notes` | 关联提示列表 |
| `requires_manual_review` | 事实不足、政策无法判断、风险或关联提示要求复核时为true |
| `issues` | 信息不足、输入或配置问题的code、message和fields |

| rule_execution_status | 含义 |
| --- | --- |
| EXECUTED | 已形成风险政策结果，包括UNCERTAIN |
| INFORMATION_ONLY | 已按信息展示模式处理 |
| CONTEXT_REVIEW | 已按关联模式处理；是否有提示取决于答案及适用性 |
| DISABLED | 本类政策关闭 |
| NOT_CONFIGURED | 本类无政策配置，保留事实展示 |
| ERROR | 单项输入格式、重复类别或类别范围错误 |

review_results每项包含 `rule_id`、`status`、`risk_level`、`reason`、`evidence_indices`、`missing_fields`、`requires_manual_review`、`recommendation`。status为TRIGGERED／NOT_TRIGGERED／NOT_APPLICABLE／UNCERTAIN；仅确定触发时输出风险等级。

context_review_notes每项包含 `rule_id`、`related_categories`、`note`、`evidence_indices`、`requires_manual_review`。related_categories仅指阅读方向，不补造相关类别事实。信息展示和关联模式的review_results为空。

issues使用明确代码区分INPUT_INVALID、UNSUPPORTED_CATEGORY、DUPLICATE_CATEGORY、UPSTREAM_INCOMPLETE、EVIDENCE_NOT_VERIFIED、COVERAGE_INSUFFICIENT、POLICY_INCOMPLETE、VALUE_NOT_COMPARABLE等原因；意外的单项处理异常记录为PROCESSING_ERROR。原始上游ERROR和未完成状态继续保留；缺失输入字段补null并在issues中标明。

## 7 判断顺序与交接

每项先形成事实状态和描述，再读取选定政策。政策关闭仍展示事实；政策开启时，事实不足则保留无法确认。事实明确后按适用性、模式和参数处理。独立的缺配置或条件不可比较问题不覆盖已确认的事实。

4号按item_index及任务标识接收结果，结合issues和复核标志安排补查、补配置或人工阅读。5号继续提供每类独立的证据及覆盖结果。批量接口只组织调用，不增加上游抽取字段。
