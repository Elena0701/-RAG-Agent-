# 全类别规则扩展推进流程

## 项目目标

面向 IPO 尽调中的受托律师及券商尽调团队，对授权取得的商业合同开展批量初筛。模块以发行人为分析对象，整理条款事实和原文证据，按预设政策生成风险提示及人工复核事项。

任务范围为 CUAD 的 36 个非基础信息类别。风险等级使用 `risk_level`，服务于初筛提示和复核顺序安排。

## 工作流程与分工

用户选择一份合同需要审查的 n 类条款。4 号组织抽取，5 号完成检索及证据核验；本模块一次接收 n 类结构化结果，内部逐类处理，一次返回 n 类结果，由 4 号汇总报告和安排后续动作。

| 负责人 | 工作内容 |
| --- | --- |
| 3 号 | 类别与政策定义、配置、规则程序、事实描述及本地测试 |
| 4 号 | 类别任务、模型抽取、批量调用、反馈补查、人工升级及报告汇总 |
| 5 号 | 原文检索、证据定位、语义支持核验及否定覆盖检查 |

## 六步推进

| 步骤 | 主要工作 | 交付及完成标准 |
| --- | --- | --- |
| 1．类别与模式总表 | 核对官方类别、答案类型和样例，确定四种模式 | 36 类均有名称、模式、政策参数和审查重点 |
| 2．文字化审查政策 | 明确必要事实、触发条件、例外、信息不足及复核要求 | 可依据文字条件编写独立的预期案例 |
| 3．统一配置模板 | 定义模式、适用范围、开关、清单／阈值、风险等级、复核要求及来源 | 参数含义统一，各类别按选定政策处理 |
| 4．扩展程序 | 实现类别注册、事实描述、通用判断及批量入口，复用单类别逻辑 | 批量结果逐项对应，单项异常独立保留 |
| 5．补充测试 | 覆盖36类的四种模式、状态分支、阈值边界、配置变化及批量异常 | 记录实际执行结果和失败原因 |
| 6．对接交付 | 使用真实上游结果联调，整理接口及运行材料 | 4／5 号的数据与状态口径一致，结果可用于反馈和报告 |

## 交接要点

- **输入：**合同标识在批量层共用；每个类别独立保存答案、证据和处理状态。全部已选类别均有输入，包括 No 或无法确认的结果。
- **处理：**按信息展示、条件触发关注、要求存在、关联复核四种模式逐类执行。
- **输出：**保留事实、证据与核验状态，附政策结果、风险等级或关联提示，并汇总人工复核要求。
- **反馈：**事实不足由 Agent 补查，政策缺项补配置，业务影响及关联解释转人工。关联复核先提供阅读提示。
