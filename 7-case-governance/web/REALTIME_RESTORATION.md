# 实时审查入口修正与真实联调记录

日期：2026年11月26日。范围仅限成员7网页外围代码、启动文档及测试。Agent核心程序、现有虚拟环境、依赖、API配置和三份正式案例文档均未修改。

## 1. 原因与修改

此前快速启动说明优先使用`--offline`，后端因此拒绝创建新模型任务；首页又默认展示历史报告，造成只有回放功能的体验。原有真实Agent调用链路仍然存在。

本次调整如下：

| 文件 | 调整内容 |
| --- | --- |
| `app.py` | 默认保留实时审查；启动终端明确输出模式；增加本地令牌保护的显式启用实时功能接口，启用本身不启动任务 |
| `static/app.js` | 正常模式打开首页进入上传工作台；右上角显示“实时审查 · 已启用”；离线模式可点击“启用实时审查”；保留历史报告深链接 |
| `task_manager.py` | 外围JSON状态保存使用独立临时文件；对短暂`PermissionError`进行有限重试；持续失败仍明确报错 |
| `agent_worker.py` | 后续意外异常额外保存脱敏`worker_error.log`，便于定位；不改变抽取、检索、核验或规则逻辑 |
| `start_realtime.cmd` | 双击启动，使用原有虚拟环境，不附加`--offline` |
| `START_HERE.md`、`README.md` | 默认说明改为实时上传审查，离线回放作为可选方式 |
| `tests/test_app.py`、`tests/test_tasks.py` | 检查模式切换权限、无隐式模型启动、Windows临时占用重试及持续写入失败 |
| `tests/browser_runtime_modes.mjs`、`tests/browser_realtime.mjs` | 分别验证实际模式切换，以及少量条款真实上传、进度、报告、导出和证据高亮 |
| 既有浏览器测试及`tests/audit_server.py` | 读历史测试显式进入报告页；兼容新生成的真实报告；隔离验收禁止启用实时功能 |

## 5. 用户启动方式

双击`web/start_realtime.cmd`，或在项目根目录运行：

```powershell
& .\4-agent\code\.venv\Scripts\python.exe -B -u .\7-case-governance\web\app.py --port 8766
```

打开`http://127.0.0.1:8766`，应看到审查工作台和“实时审查 · 已启用”。旧服务需先在其原终端按`Ctrl+C`停止，再重启并`Ctrl+F5`刷新。完整说明见[START_HERE.md](START_HERE.md)。历史回放在正常模式下同样可用，打开历史不会调用API。

自动化真实联调脚本默认复用已经保存的任务ID，防止再次计费。运行`browser_realtime.mjs --clause Q1`只读取本次既有任务；不要删除保存的任务ID文件来重复付费测试。
