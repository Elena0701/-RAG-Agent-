# 邀请码登录与小组共享使用说明

本版本仍复用现有Agent、虚拟环境和模型配置。新增的是成员7外围的身份、额度、任务归属和局域网入口，不改变RAG、事实抽取、语义核验或业务规则。开发与验收没有新增付费模型调用。

## 1. 先选择使用方式

| 方式 | 网站后台在哪里运行 | 组员电脑需要安装什么 | 使用哪份API配置 |
| --- | --- | --- | --- |
| 同一局域网共享，推荐小组体验 | 成员7的电脑 | 只需要浏览器 | 成员7主机已有配置，费用由该账户承担 |
| 组员独立运行一份 | 每位组员自己的电脑 | Python、项目依赖及模型文件 | 该组员自己配置的服务 |
| 跨网络公开网址 | 持续运行的服务器 | 浏览器 | 服务器管理者配置的服务 |

本次已经实现前两种方式需要的程序入口与说明。没有部署到云服务器，也没有提供公网域名。局域网地址不等于公网网址。

## 2. 登录到底如何开放实时审查

### 2.1 游客可以做什么

不登录也能查看已公开的真实课堂案例、执行记录、原文证据、原生JSON导出和打印报告。后台不会因为打开页面或回放而调用模型。

游客点击“登录后启动真实审查”，会打开邀请码登录窗口。即使绕过页面直接请求创建任务，后端也会返回401，不会启动Agent。人工复核记录的提交同样需要登录。

### 2.2 管理员发放邀请码

已在本机创建8个邀请码，私有交接文件为：

```text
7-case-governance/web/data/access/初始邀请码_仅管理员查看.txt
```

| 初始身份 | 权限 | 每次条款上限 | 每日任务上限 | 邀请码有效期 |
| --- | --- | ---: | ---: | ---: |
| 成员7管理员 | 查看所有新任务及报告，可启用离线服务的实时功能 | 41 | 5 | 30天 |
| 成员1、2、3、4、5、6、8，各自独立 | 上传审查及查看本人的新任务、报告 | 5 | 3 | 7天 |

用记事本或VS Code打开该文件，找到对应成员的一段，**只发送其本人对应的邀请码**。不要把整个文件发给全组，也不要把它加入作业压缩包或Git。

邀请码不是模型API密钥。使用者无需输入API密钥，所有实时审查使用主机已有的后台模型配置。这里的登录是课程演示用的邀请码身份，不是实名认证，也不验证法律专业资质。

### 2.3 使用者登录并审查

1. 打开你提供的网页地址，点击右上角“邀请码登录”。
2. 粘贴自己的邀请码，点击“登录并开放实时审查”。
3. 页面显示身份、单次条款上限和今日剩余额度；右上角显示“实时审查 · 已启用”。登录本身不调用模型。
4. 上传PDF或UTF-8 TXT，只上传合同正文，不上传CUAD人工标注。
5. 选择条款，点击“启动真实Agent审查”，阅读调用规模后确认。这一步才提交任务并可能产生模型费用。
6. 查看真实进度，完成后打开报告及证据溯源。新上传的合同和报告只对该身份及管理员开放。
7. 点击右上角的身份按钮可查看权限和退出。退出不会停止已经提交的后台任务；重新登录后到“历史案例 → 刷新任务”查看。

### 2.4 额度和会话如何计算

- 每次登录有效8小时；邀请码过期或被管理员撤销后，相关登录立即失效。
- 每日额度按北京时间零点重置。限制的是**已创建的审查任务数**，不是模型请求数或金额。
- 一个5类任务首轮通常约10次模型请求，补查、No覆盖核验及SDK重试可能增加请求。每天3个任务不等于每天只调用3次模型。
- 任务创建后的失败、取消或保护性停止也计次，因为可能已经发生模型请求。文件格式错误、超出条款权限或服务忙等创建前拒绝不计次。
- 同一请求的重复提交不重复启动、也不重复扣次；修改合同或参数后应重新选择并提交。
- 当前同一服务一次只运行一个审查任务；其他成员会收到“已有审查正在运行”，需要等它完成再提交。没有实现后台排队。
- 一个人的邀请码在多台设备登录，仍共享同一身份、额度和私有任务。因此不要转发邀请码，也不要多人共用一个码。

### 2.5 数据如何隔离

访问新任务、报告、合同文本、证据、下载、打印和停止接口时，后端检查任务所属身份。猜到任务ID或报告ID也不能查看其他成员的私有内容。管理员可查看全部新任务，便于课程管理。

首次启用时，后台把当时已有、没有所有者的课堂报告登记为公开历史；后续上传不会自动公开。公开历史清单保存在访问数据库中，不修改原生报告。新任务的所有者记录在外围`task.json`中，原生Agent报告和对话内容不被改写。

## 3. 让同组成员直接通过浏览器访问你的电脑

### 3.1 在你的电脑启动共享服务

先在旧服务原来的终端按`Ctrl+C`停止它，避免端口冲突。然后双击：

```text
7-case-governance/web/start_shared.cmd
```

也可以在项目根目录的PowerShell执行：

```powershell
& .\4-agent\code\.venv\Scripts\python.exe -B -u .\7-case-governance\web\app.py --port 8766 --lan
```

后台仍然使用已有虚拟环境和API配置，不需要重建环境。启动终端必须保持运行；你关闭电脑或停止服务后，其他成员就无法访问。

### 3.2 找到应该发给组员的地址

终端会输出：

```text
LOCAL_URL=http://127.0.0.1:8766
GROUP_URL=http://某个网卡IP:8766
```

你的浏览器可以使用`LOCAL_URL`。组员使用与你当前网络对应的`GROUP_URL`，**不要把127.0.0.1发给他们**。

一台电脑可能同时存在Wi-Fi、以太网、VPN和VMware虚拟网卡，所以可能打印多个候选地址。可在终端运行：

```powershell
ipconfig
```

找到当前连接小组网络的“无线局域网适配器 WLAN”或“以太网适配器”下面的IPv4地址。不要直接选择VMware虚拟网卡地址。组员需要连接允许设备互访的同一网络；同一校园Wi-Fi也可能启用设备隔离。

例如你的有效IPv4是`192.168.1.23`，端口是8766，则发给组员：

```text
http://192.168.1.23:8766
```

这是格式示例，不是本项目已经获得的公网网址。

如果正确网卡IP没有自动出现在候选地址中，可以显式允许它：

```powershell
& .\4-agent\code\.venv\Scripts\python.exe -B -u .\7-case-governance\web\app.py --port 8766 --lan --allow-host 192.168.1.23
```

把示例IP换成实际IP；`--allow-host`只填写IP或主机名，不填写协议、路径或端口。网络变化后需重启服务以重新识别地址。

### 3.3 在组员电脑上操作

1. 保持你的共享服务运行。
2. 组员打开Chrome或Edge，在地址栏输入你发出的有效地址。
3. 历史案例可以直接查看；实时审查输入其个人邀请码。
4. 上传合同、选条款并确认启动。无需安装Python、VS Code或模型，也无需配置API。

如果只需要自己使用，仍可双击`start_realtime.cmd`，它默认只监听本机。两种入口都需要邀请码登录才能新建实时审查。

### 3.4 组员打不开时如何排查

| 现象 | 检查方式 |
| --- | --- |
| 你的浏览器也打不开 | 确认终端仍运行，检查是否端口占用，网址端口与命令一致 |
| 你能打开，组员连接超时 | 检查是否使用`--lan`、是否选对物理网卡IP、是否同网、是否防火墙拦截 |
| 浏览器返回403 | 检查访问IP是否在启动时允许的地址中；必要时使用`--allow-host 实际IP`重启 |
| 同一校园网仍不通 | 校园网可能隔离客户端，可换允许互访的个人热点或其他可信网络 |
| 登录提示无效 | 检查是否复制完整、是否到期或被撤销，以及是否登录了另一台独立服务器 |
| 登录成功仍不能启动 | 查看条款上限、每日剩余、服务是否离线、是否已有任务运行 |

Windows首次提示Python网络访问时，只在你信任的小组网络中允许“专用网络”。本轮没有自动修改系统防火墙。如果确需手动添加规则，可由管理员在可信专用网络上运行以下限定规则：

```powershell
New-NetFirewallRule -Name 'ContractReviewWorkbench-8766' -DisplayName '合同初审工作台 8766' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8766 -Profile Private -RemoteAddress LocalSubnet
```

演示后删除这条规则：

```powershell
Remove-NetFirewallRule -Name 'ContractReviewWorkbench-8766'
```

更换端口时同步修改命令和规则。不要为演示关闭整个防火墙。本版本局域网HTTP适用于可信小组网络；邀请码登录不提供传输加密，公网使用需配置HTTPS。

## 4. 管理员如何新增、补发和撤销邀请码

在项目根目录运行以下命令。无需停止服务，也不会调用模型。

### 新增普通成员

```powershell
& .\4-agent\code\.venv\Scripts\python.exe -B .\7-case-governance\web\manage_access.py create --name '新成员姓名' --days 7 --max-clauses 5 --daily-limit 3
```

终端仅此次显示明文邀请码，请单独交给本人；数据库只保存其摘要。现有初始码已准备好，不要为了查看它重复创建同名身份。

给老师一个少量体验权限的示例：

```powershell
& .\4-agent\code\.venv\Scripts\python.exe -B .\7-case-governance\web\manage_access.py create --name '授课老师' --days 14 --max-clauses 2 --daily-limit 1
```

### 查看身份编号及权限

```powershell
& .\4-agent\code\.venv\Scripts\python.exe -B .\7-case-governance\web\manage_access.py list
```

列表不显示邀请码明文。保管好初始交接文件；其他新生成的邀请码遗失后，需撤销旧码并重新发放。

### 撤销某个身份

```powershell
& .\4-agent\code\.venv\Scripts\python.exe -B .\7-case-governance\web\manage_access.py revoke --id '替换为列表中的完整编号'
```

撤销会使该身份现有登录失效，但不会自动中断它此前已经提交的任务。管理员可在网页任务列表中停止该任务；已经发生的模型调用仍可能计费。重新发放的新码代表新身份，原有私有任务仍由管理员可见。

管理员邀请码只能由主机控制台发放；网页没有公开注册或自行提权入口。CLI创建管理员时默认上限为41类、每日20次，可用参数设得更小；本机初始管理员已明确设为每日5次。

## 5. 组员在自己电脑上独立运行

这与通过浏览器访问你的主机是两种方式。独立运行不需要你电脑开机，但需要组员自己的运行环境和API配置。

### 5.1 获取必要文件

复制项目代码并保持现有目录结构，包括Agent、规则、检索模块及成员7网页与脚本。仅复制`web/`或`index.html`无法运行Agent。

不要复制你的真实`.env`、`deepseek.local.env`、虚拟环境、模型缓存、`web/data/`及`web/qa/`。不需要完整CUAD数据集和人工标注。若需要历史回放，应另提供经选择的真实报告及其对应合同、日志、元数据和坐标映射；这些产物保持原样。

### 5.2 在新电脑安装环境

以下步骤只针对尚未准备环境的组员电脑；**成员7当前电脑不需要重新创建环境或重装依赖**。

安装Python 3.12，打开PowerShell，进入组员自己保存的项目根目录，再运行：

```powershell
py -3.12 -m venv .\4-agent\code\.venv
& .\4-agent\code\.venv\Scripts\python.exe -m pip install -r .\4-agent\code\requirements-lock.txt
& .\4-agent\code\.venv\Scripts\python.exe -m pip install -r .\7-case-governance\web\requirements.txt
```

首次实时审查需要准备或下载Embedding模型。依赖安装和首次模型准备可能耗时，需要网络；不是点击网页就自动具备全部环境。

### 5.3 配置该电脑自己的模型服务

按[成员4运行说明](../../4-agent/code/README.md)中“配置两个模型服务”设置事实抽取和证据语义核验，使用自己的密钥、地址和实际可用模型。只配置抽取不配置核验，可能出现候选答案成功但证据无法确认。

只回放历史时无需配置API。不要将成员7的真实密钥放入分享包。独立主机的费用由该主机配置的账户承担。

### 5.4 在新电脑生成本机邀请码并启动

```powershell
& .\4-agent\code\.venv\Scripts\python.exe -B .\7-case-governance\web\manage_access.py create --name '本机管理员' --role admin --days 30 --daily-limit 5
& .\4-agent\code\.venv\Scripts\python.exe -B -u .\7-case-governance\web\app.py --port 8766
```

保存终端显示的本机邀请码，浏览器打开`http://127.0.0.1:8766`后登录。成员7主机的邀请码不能用于另一台独立主机，因为各自数据库和身份不同。准备好环境后，后续可以直接双击`start_realtime.cmd`启动。

## 6. 新文件与数据存放

| 文件或目录 | 内容 | 是否随代码分享 |
| --- | --- | --- |
| `access_control.py` | 邀请码、8小时会话、登录限流、每日额度及公开历史清单 | 是 |
| `manage_access.py` | 主机管理员创建、查看、撤销邀请码 | 是 |
| `sharing_network.py`、`start_shared.cmd` | 网卡候选地址及局域网启动 | 是 |
| `static/access.js` | 登录、权限展示及退出交互 | 是 |
| `data/access/access.sqlite3` | 邀请码摘要、会话摘要、额度和公开历史清单 | 否，主机私有 |
| `data/access/初始邀请码_仅管理员查看.txt` | 本机初始邀请码明文交接文件 | 否，仅管理员保管 |
| `data/reviews/` | 明确提交的独立人工复核记录 | 按提交范围选择，不随意公开 |
| `results/web_runs/<任务ID>/task.json` | 外围任务参数和所属身份 | 新任务默认私有 |
| `results/web_runs/<任务ID>/reports/`等 | 原生Agent报告、对话、JSONL、断点及外围进度 | 按授权选择，保留原样 |
| `qa/` | 本地测试结果、截图和隔离测试文件 | 不作为真实案例或账号分发 |

`data/`、`qa/`已由网页`.gitignore`排除。不要删除访问数据库来“重置次数”：这会丢失身份及权限对应关系。独立人工复核仍保存为外围记录，不覆盖原始Agent决策。

## 7. 当前验收和适用边界

测试结果见[共享版测试报告](SHARING_TEST_REPORT.md)。本机实际网卡地址可打开服务、登录及回放，已验证；第二台实体电脑的连接仍需小组按第3节现场验证，不能仅凭本机测试保证校园网互通。

本次未重跑付费审查，权限后的任务入口使用受控进程替身验证。此前真实Agent联调产物继续保留，登录门禁不更改它的调用逻辑。受控测试没有生成冒充自然运行的报告。

该版本适合可信小组网络及本地课堂演示，不是已经完成公网部署的多租户服务。公网使用仍需HTTPS、正式WSGI部署、网络及存储隔离、监控和持续运维。后台仍为单任务运行，没有金额级预算控制或后台任务队列；邀请码额度不能替代模型服务端费用上限。
