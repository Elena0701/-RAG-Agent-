# 邀请码与小组共享版测试报告

日期：2026年11月26日。范围：成员7网页的访问控制、额度、任务归属、登录交互、局域网入口及既有真实报告回归。**本轮开发与验证未发起付费模型调用**，没有重新生成案例来改善结果。

## 1. 实现范围

- 游客可回放已登记的课堂历史案例；新建审查和提交人工复核记录必须登录。
- 一人一个邀请码，后台只保存邀请码和会话摘要；登录Cookie为HttpOnly、SameSite=Lax，会话8小时。HTTPS部署可使用`--secure-cookie`。
- 登录失败限流、邀请码过期与撤销；角色及单次条款数、每日任务数均由后端判断。
- 额度使用SQLite事务控制并发；同一请求不重复计次；创建前拒绝释放预留，已创建任务失败或停止仍计次。
- 新任务记录所属身份。报告、正文、证据、下载、打印、任务状态及停止接口检查归属；管理员可管理所有任务。
- 初始历史清单登记后不自动公开后续上传；原生Agent报告不被改写。
- `start_shared.cmd`及`--lan`提供局域网入口；默认`start_realtime.cmd`继续只监听本机。
- 原有Agent调用、模型配置、检索、核验、业务规则和补查逻辑保持复用。

## 3. 真实记录、受控测试与未验证范围

### 真实已有记录

历史页面使用主机已经存在的原生JSON报告及实际文本、日志。验收时发现6份完整报告，包括既有CUAD-003记录；本任务未运行这些合同。CUAD-004仍显示真实41项、25项自动接收、16项人工升级。其统计、Q1–Q5规则未执行以及Q16实际补查等语义保持一致。

真实网卡访问检查实际启动`app.py --port 8773 --lan`，在浏览器通过主机网卡地址加载服务、使用初始管理员邀请码登录、查看CUAD-004报告并高亮Q16原文，最后退出。只提交登录和退出，没有请求`POST /api/tasks`，管理员任务用量仍为0。

### 明确的受控测试

`tests/sharing_test_server.py`使用真实Flask路由、SQLite、Cookie和上传校验，但将子进程启动器替换为受控对象，并阻断外网连接。浏览器创建的任务仅位于`qa/`临时目录，没有模型回答或原生审查报告，不混入真实历史结果。

`tests/audit_server.py`强制离线，使用临时管理员身份完成表单测试。接受、修正、驳回、补充材料均标为受控界面操作，只保存到临时目录，不属于真实人工复核结果。服务关闭后删除临时记录及测试邀请码。

登录后按钮校验脚本仅在浏览器中暂时展示正常启动能力，实际后端仍离线，创建请求返回503，未启动Agent。

### 本轮没有执行的检查

- 没有在权限改造后再次付费运行模型；上传后调用现有虚拟环境和工作进程的边界由受控测试验证。此前实际模型联调见[实时联调记录](REALTIME_RESTORATION.md)。
- 没有使用第二台实体电脑连接，不能声称已经证明校园网、Wi-Fi或防火墙互通；已验证同一主机经其实际网卡地址访问。另一台电脑需按[共享说明](SHARING_GUIDE.md)现场验收。
- 没有新增真实PDF模型审查；PDF上传及现有解析由已有无模型受控测试覆盖。
- 没有云部署、HTTPS证书、跨公网访问、多人压力测试或后台排队。当前一次只审查一个任务，其他请求得到服务忙提示。

## 4. 文件与凭据检查

`qa/sharing_integrity_results.json`记录了142个既有文件的比较。其中Agent核心和原始运行产物未发生指纹变化；三份正式案例Markdown在本轮工作期间与基线不同，本网页任务未对它们写入，保留当前版本并单列，不能将它们描述为“指纹未变”。

网页及测试文件扫描未发现已配置模型API密钥明文。真实密钥没有写入前端、登录配置或邀请码交接文件。`web/data/`与`web/qa/`已被Git忽略。

初始邀请码交接文件包含网站邀请码明文，只供主机管理员分发；它不是API配置，但同样不应进入共享代码包或作业压缩包。公开使用时应通过HTTPS传输邀请码，当前可信局域网HTTP不提供链路加密。

## 5. 复核入口

在项目根目录可运行无模型接口测试：

```powershell
& .\4-agent\code\.venv\Scripts\python.exe -B .\7-case-governance\web\tests\test_app.py
& .\4-agent\code\.venv\Scripts\python.exe -B .\7-case-governance\web\tests\test_tasks.py
& .\4-agent\code\.venv\Scripts\python.exe -B .\7-case-governance\web\tests\test_access.py
```

浏览器自动化使用开发机随附Node/Playwright及已安装Chrome，不是网站运行依赖。受控登录界面验收需要先启动`tests/sharing_test_server.py`，然后运行`tests/browser_sharing.mjs`；全面离线验收使用`tests/audit_server.py`与`tests/browser_audit.mjs`。这些测试使用临时身份，不操作正式人工复核记录。

旧的真实浏览器联调脚本现在也要求邀请码登录。可将一个邀请码保存为仅本机保管的单行文件，把`WORKBENCH_INVITE_FILE`设为该文件路径；脚本不会自动读取本机初始邀请码来付费执行。已有保存任务ID时只回放，不应删除ID文件来重复计费。
