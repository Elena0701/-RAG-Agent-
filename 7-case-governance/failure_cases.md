# 真实失败案例与未验证风险分析


## 1 分析目标、证据等级与判定原则

失败分析旨在定位错误进入流程、是否被检测、是否影响最终动作，以及补查和人工复核是否提供有效保护。候选错误、证据错误、规则不能判断和正常政策提示属于不同现象：候选虽错但最终升级，和错误获自动接收，业务影响不同；转人工本身不必然是失败。

| 证据等级 | 本文来源 | 可以支持的结论 | 不能支持的结论 |
|---|---|---|---|
| N：自然运行 | 三份CUAD真实GPT输出、既有demo认证失败、首次沙箱中断 | 本次确实发生的输入、轨迹和状态 | 不能据此推导总体错误率或完整法律结论 |
|  |
| P：代码推导的潜在风险 | 解析器、提示词、规则、缓存与工作流实现 | 可达分支、缺少机制及需要验证的假设 | 未运行场景不能描述成已出现故障 |

参考依据分别来自合同原文、当前类别定义、保存的演示政策及协议不变量。CUAD是条款标注，空标注不证明不存在，有答案也不直接提供风险等级。本文的‘疑似漏报/误拒’是自动辅助评估，尚无独立专业人工裁决；对可直接核查的文本遗漏与状态流转作确定记录，对类别及法律解释保留争议。

### 1.1 什么算失败：分别判断内容、阶段和最终处理

失败不能仅按最终ACCEPT或ESCALATE判定，应先明确目标类别、原文证据和预期处理，再判断哪一环节偏离要求。ACCEPT的结果仍可能存在漏报或证据遗漏；正确事实命中政策后转人工则不是算法失败。对错误是否存在及防护是否有效，应分别记录。

| 观察情形 | 评价口径 | 本轮例子或判断边界 |
|---|---|---|
| 误报、漏报或条件/例外遗漏 | 依据原文和类别定义评价内容；有争议时标为疑似，不以gold空标注直接裁决 | Q35疑似漏报及核验理由问题，Q36引文遗漏例外 |
| 候选错误被拦截并纠正 | 属阶段性错误与防护成功，不能继续写成最终错误答案 | Q16首轮No经补查改为Yes；最终证据完整性仍单独评价 |
| 技术故障或证据无法形成 | 记录自动化未完成、是否保留结果和人工升级；不能自动等同事实答案错误 | N06认证异常，Q38引文无法定位 |
| 材料不足或语义不确定后合理升级 | 可作为证据不足/人工升级分析，不预设程序处理错误 | 候选、原文和无法确认原因需分别核查 |
| 正常政策触发后转人工 | 属预期业务处理，不算识别失败 | 已核验事实命中演示政策的Q19等 |
| 解释范围、类别口径尚有争议 | 作为边界观察，说明待确认内容，不计入已确认误报/漏报 | CUAD-008 Q19；不能因五项ACCEPT而宣称均正确或均失败 |

### 1.2 逐个案例的分析步骤

先说明审查目标及参考行为来源，再保存实际候选、引文、状态和全部尝试；沿输入、检索、抽取、核验、规则、动作定位首次分歧，区分错误被拦截、补查纠正、合理升级与错误被接收；最后评估可能影响、现有防护及改进，并给出原始报告、日志、原文或测试位置。缺少裁决依据时保留待确认，不为凑失败类型而强行定性。

本节使用已有真实运行和明确标注的受控测试分析失败机理，不以整份合同最终处于失败状态作为选样条件。候选层面的Yes/No是条款识别结果，风险误报/漏报还需要另外明确业务政策和人工风险参考。


### N09—N10 其他真实观察：日期冲突与格式归一化

## 4 综合分析与改进优先级

优先处理会穿过全部门槛的错误：Q35的No/PASSED/ACCEPT与Q36例外遗漏，说明存在格式合规但事实范围不完整的残余风险。其次处理返回值中的服务故障与阶段异常分类，避免无效补查成本；再改进引文复制、别名归一化、定义口径和政策预检。仅提高top-k无法解决认证、政策适用性或同一模型对例外的误读。

现有防护对错位、覆盖不足、格式错误和无法确认具有实际拦截作用，但应分别陈述拦截的对象与未覆盖的风险。自然案例可用于解释机理，潜在风险只能作为后续验证议题。正式误报/漏报数量和风险等级准确率需要独立人工裁决，不以本节的辅助标签代替。
